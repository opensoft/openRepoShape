# openRepoShape v1.0.0

openRepoShape is the convention, as data and as running code, for a project
that spans several repositories: what they are called, how they are pinned to
each other, how one clone brings the whole project down, and what an AI
assistant does when asked to scaffold one. Its preferred shape, the Triad, is an
assembly root that mounts a spec leg and a code leg. The shape is elective and
confers nothing. Version 1.0 promises that every procedure in AGENTS.md works
end to end for ordinary repositories on Linux, macOS and Windows. On Windows,
`make park` and `make resume` run under WSL2, as the README says: native
Windows parks nothing. The release is tagged only when every in-scope issue is
closed and the full test suite passes on all three systems on the release
commit. Edge cases that only unusual input reaches
are listed below as known limits.

## What 1.0 contains

- **New project:** `openRepoShape <Project> --org <org>`, or `./setup.sh`, or
  `py setup-project.py` on Windows. It runs a preflight, checks the names,
  shows the plan and asks for one typed `yes`.
- **Direct scaffold:** `scaffold-project.py`. Add `--pin open<Product>@<commit>`
  for a declared descendant.
- **Adopt in place:** `adopt-project.py plan`, then `check`, then `execute`.
- **Compliance check:** `openRepoShape --doctor [<path>]` or
  `shape-doctor.py --root <path>`.
- **Stay current:** `update-shape.py check`, then `apply`.
- **Advance a leg:** `scripts/bump-leg.py --root <path> --leg spec|code --to <40-hex>`.
- **Families:** `scripts/family.py init|add|bump|remove|siblings`.
- **Park and resume:** `make park` and `make resume`.
- **Each project's own gate:** `make bootstrap` and `make validate` run pinned
  copies of the scripts, so the gate never needs this standard.

## Requirements and platforms

- `git` and Python 3.9 or newer. The tools use the standard library only.
- `gh`, logged in, wherever a tool creates repositories or pull requests on
  GitHub. `git-filter-repo` is needed for adoption only. `make` is optional.
- `openRepoShape --preflight` checks the machine and creates nothing. On
  Windows, run `py setup-project.py --preflight`. It offers each missing
  install behind a typed `yes`.
- **Linux** and **macOS** are supported, and the stock macOS `/bin/bash` 3.2 is
  enough. **Native Windows** uses `setup-project.py`, after
  `git config --global core.autocrlf false`. **WSL2** runs the bash entry
  points. Park and resume do not work on native Windows; run them under
  WSL2.
- CI runs the full suite on `ubuntu-latest`, `macos-latest` and
  `windows-latest`. On Windows the adoption suites skip, because
  `git-filter-repo` is not installed there (#471).

## How to pin 1.0.0

A project pins the standard in `contracts/shape-pin.yaml`, which always
records a 40-hex commit. Name `<release-commit>` itself rather than the tag: a
tag can be moved and a commit cannot, as the README and AGENTS.md say of every
pin.

- **New project:** run
  `OPENREPOSHAPE_REF=<release-commit> openRepoShape <Project> --org <your-org>`.
  The command forwards `--shape-ref <release-commit>` to `setup.sh`. Outside a
  checkout, `setup.sh` and `setup-project.py` take `--shape-ref` directly.
- **Existing project or family holder:** run these from a checkout of the
  standard. `check` lists the files that change. `apply` says how many it
  will re-copy and asks `Type yes to proceed:` before it writes anything:

  ```sh
  ./update-shape.py check --root <path> --at <release-commit>
  ./update-shape.py apply --root <path> --at <release-commit> \
      --branch shape/update-<release-commit>
  git -C <path> push -u origin shape/update-<release-commit>
  ```

  Then open a pull request from that branch.

- **Confirm:** run `./shape-doctor.py --root <path>` from a checkout at
  `<release-commit>`. `COMPLIANT`, exit 0, means the pin names that commit.

## What changed on the way to 1.0

### adopt-project.py

- **In-place adoption.** The repository becomes the assembly root and keeps
  its name and history. The legs are extracted with `git filter-repo`, and the
  split lands as one pull request. Every source path is verified by blob sha.
  The plan asks about any path it cannot place, an empty leg is seeded with
  `--allow-empty-leg`, and the `xf-project-<id>` topic is set
  (#5, #16, #17, #24).
- **Refused before any leg exists.** `execute` refuses everything `check`
  finds before it creates a leg. That covers bad mount paths, root paths that
  clash with the shape's files, values no file can hold
  (`adopt-unwritable-value`), and paths it cannot extract, which `plan` now
  asks about
  (#170, #187, #198, #231, #270, #313, #353, #377).
- **Submodules.** `.gitmodules` stays in one leg with its submodules. An
  unreadable one is a `plan-gitmodules-unreadable` finding, not a crash, and
  relative URLs are checked from both sides. Verification accepts no root
  gitlink but the two leg mounts, each at the commit pushed to its leg
  (`adopt-root-submodule`, `adopt-mount-commit` and others)
  (#162, #173, #194, #226, #240, #245, #268).
- **Ignore rules and odd names.** Shape files are committed even when the
  source's `.gitignore` matches them, and leg mounts use `--force`. Findings
  spell out control characters and bytes that are not UTF-8, follow-up
  searches take paths literally, and a cp1252 console gets escaped names
  (#182, #200, #223, #228, #246, #247, #378).
- **Late failures.** After a leg exists, a failure prints `REFUSED <step>.`
  and what the run left behind (#445). Exit 1 means the verification failed.
  Exit 2 with `IS pushed` is finished by hand with the command it prints,
  never by re-running (#371).

### update-shape.py and bump-leg.py

- **Re-syncing copies.** `check` gives each pinned file a verdict
  (`unchanged`, `upstream-changed`, `locally-modified` or `both`) and names
  files the standard has added (`upstream-added`). It exits 1 when there is
  work to do. `apply` re-copies and re-pins, and rolls back if the project's
  validators fail. `--add` and `--accept-local` each name one file and can be
  repeated. Family holders, and their README's `Shape:` line, update the same
  way, and the commit and refusals name the holder's own manifest
  (#10, #29, #47, #52, #85, #152, #159).
- **Landing.** `apply --branch` takes `--trailer` lines. The `gh pr create` it
  prints targets the root's own branch and repository. A failed push keeps the
  commit and prints a NEXT line. A later `--pr` run opens the pull request,
  unless the tree has changed since (`update-rerun-uncommitted`)
  (#112, #218, #227, #379).
- **Clean rollback.** A failure before the commit restores everything.
  Additions through links or under files are refused (`update-add-symlink`,
  `update-add-not-a-directory`). A shape pin whose `files:` is not a list is
  refused `update-pin-row`, and the project's validators report
  `shape-pin-row`, where all of them ended in a traceback. Pin rewrites keep
  layout and comments, and non-ASCII project names work under cp1252
  (#224, #233, #269, #281, #343, #346, #380).
- **bump-leg.py.** One commit moves a leg's gitlink, pin and workflow
  references, and `--dry-run` shows `old -> new` and the trailers first.
  Untracked workflows are refused (`bump-leg-workflow-untracked`), and
  unreadable files are refused by name. Case-only renames are followed, and
  any failure rolls back (#35, #151, #222, #264, #344, #352, #403).

### setup, scaffold, family and the shared helpers

- **Front door.** `setup.sh` self-bootstraps from upstream with an explicit
  `--org`, so no fork is needed. It is a shim over `setup-project.py`, the
  native Windows way in. `openRepoShape` installs as a command. The preflight
  offers installs behind a typed `yes`. `--local-remote-dir` rehearses a run
  with nothing created on GitHub, and `--family` lands the clone in a family
  folder. `setup.sh --help` outside a checkout answers without cloning anything
  (#2, #3, #14, #37, #53, #56, #57, #60, #62, #65, #75, #78, #452).
- **Naming and descent.** Names are classified offline against six families.
  A descendant must pin its `open<Product>`, directly or through a recorded
  chain. The default `reference:` follows the election date. The Triad
  advisory speaks once and never blocks, and `single-repository.yaml` silences
  it (#4, #6, #19, #27, #42, #45, #86, #164).
- **Scaffold refusals before anything exists,** dry runs included:
  - colliding leg paths (`scaffold-leg-path-collides`);
  - pins the shape cannot write (`scaffold-pin-collides`);
  - bad chain links;
  - manifest values the project would misread, and text no file can hold;
  - a `--tracking-branch` git would not take as a branch name, here and in
    `family.py init`.

  Shape files and leg mounts get past the operator's own ignore rules, and
  templates are filled in one pass
  (#185, #201, #234, #235, #256, #271, #314, #316, #351, #355).
- **Each project's own gate.** `make bootstrap` places each leg at its pin,
  and `.gitattributes` keeps LF line endings. `AGENTS-shape.md` carries the
  rules for assistants, and a `<user>-wip` template ships too. The `validate`
  workflow reads private legs with a GitHub App or `SHAPE_LEGS_TOKEN`, and
  carries on with a warning without one. `validate-pins.py` rechecks
  neutral-product pins offline where it can, and refuses `git-not-runnable`
  (exit 2). `make bootstrap` escapes what the console cannot print, so a
  `name` such as `日本` under `PYTHONIOENCODING=ascii` no longer ends it in a
  traceback
  (#1, #7, #8, #12, #13, #15, #18, #25, #30, #58, #154, #312, #446, #456).
- **Families.** A holder pins member roots under `members/`, and
  `make siblings` clones working copies beside it without moving anything.
  `add`, `bump` and `remove` have `--dry-run`. They check before they write,
  and restore the holder on failure. `add` refuses duplicates by name or id
  (`member-already-present`, `member-duplicate-id`). A repeated `bump` says
  `nothing to do` and exits 1
  (#16, #79, #219, #221, #236, #308, #315, #317, #318, #345, #350, #381, #399, #400, #406, #416).
- **Park and resume.** `make park` and `make resume` hand off to the Speckit
  git extension. The installed commands moved to opensoft/openRepoTools
  (#80, #83, #93, #94).
- **Shared helpers.** The YAML reader refuses a file it cannot open or
  decode as UTF-8 (`yaml-unreadable`) and text it cannot parse
  (`yaml-unparsable`), and several flow and quoting forms it used to misread
  are now read exactly or refused. Output from git and `gh` is read as UTF-8
  under any locale. "Same repository" now has one definition
  (#156, #160, #193, #230, #244, #257, #265, #284, #390).

### shape-doctor.py

- **One verdict.** `openRepoShape --doctor` writes nothing into the
  repository and fetches nothing into it. Run outside a checkout of the
  standard, it first clones the standard into a temporary directory. It prints
  a row per check, then one verdict:
  - `COMPLIANT`: exit 0;
  - `COMPLIANT, SHAPE BEHIND`, `DRIFTED`, `MISPLACED` or `INVALID`: exit 1;
  - `NOT A SHAPE ROOT`: exit 2;
  - `CANNOT ANSWER`: exit 3.

  Only a `FINDING` moves the verdict. The machine check is now `--preflight`
  (#96).
- **Placement.** The `placement` row checks each leg's paths against the
  adoption policy. `--placement-plan` writes a plan for a person to resolve
  (#100, #186).
- **NEXT commands you can paste.** They are quoted for sh or PowerShell, use
  `Copy-Item -LiteralPath` on Windows, and set the `PYTHONPATH` a validator
  needs (#102, #106, #107, #108, #110, #287, #311, #354).
- **More accurate verdicts.** An unloadable manifest or shape pin is now
  `INVALID`, where it was `NOT A SHAPE ROOT` or `CANNOT ANSWER`. A misplaced
  `family.yaml` is a `manifest kinds` finding, and a crashed validator says so.
  A fork beside a holder is no longer taken for the member
  (#147, #220, #232, #267, #357, #375, #404).

### The test suite, CI and the docs

- **Three operating systems.** Every pull request runs the full suite on
  Linux, macOS and Windows, though on Windows the adoption suites skip until
  #471 is fixed. Every push to `main` runs it on Linux. actionlint checks this
  repository's workflow and both shipped ones
  (#9, #11, #53, #57, #124, #129, #336).
  <!-- drop the Windows qualifier once #471 lands as proposed -->
- **Hermetic tests.** No test reaches the real `gh` (#274, #349), and the
  suite scaffolds into local bare repositories, never GitHub. Tests no longer
  depend on the host's paths, pin-source variables or git identity, and a
  failing assert names what broke (#64, #116, #120, #128, #131, #310, #335).
- **Docs.** The README has a quick start for each platform, and
  `docs/handbook.html` is a one-page reading of it. `docs/cli.md` is generated
  from every tool's `--help`. A test ties each refusal code AGENTS.md names to
  the tool that prints it, and the docs name `$AGENT_PROTOCOL_ROOT` rather
  than a fixed path. `adopt-project.py plan --help` says what `--spec-path`
  and `--code-path` are, their defaults, and the two refusals `plan` makes on
  them (`adopt-bad-leg-path`, `adopt-leg-path-collides`)
  (#23, #46, #70, #71, #73, #88, #90, #98, #161, #309, #396, #401).
- **Maintainability.** Static-analysis findings were fixed, long functions
  split and docstrings corrected, with no change in behaviour
  (#67, #117, #121, #125, #139, #140, #141, #142, #143, #144, #145, #398).
  openRepoShape itself stays a single repository (#372).

## Known limits

Each line names the input that triggers the limit, then what you see. Each
limit stays open under its area's tracking issue.

### [adopt-project.py](https://github.com/opensoft/openRepoShape/issues/457)

- #178: A dangling or outward symlink the root keeps at or above a path the shape writes: `check` passes, then `execute` crashes or writes outside the assembly after both legs are pushed.
- #181: A source holding a file or directory named `null`, `true` or `false`: `plan` writes the name unquoted, so `check` finds the path in no entry, and an entry that covers nothing, until the plan is fixed by hand.
- #183: A root-kept symlink to elsewhere on disk, or a link loop: the shape's files are written through the link, or the run crashes, after both legs are pushed.
- #189: A source with a submodule kept in a leg: the doctor can only note it, because the assembly does not record which leg was chosen.
- #293: A hand-edited `follow_ups:` that is not a list: `check` and `execute` end in a `TypeError` traceback, `execute` after both legs exist.
- #303: A source symlink with an empty target: `check` passes. With symlinks on, `execute` fails after both legs exist; with `core.symlinks=false`, it says `adoption verified` over a tree a clone with symlinks on cannot check out.
- #328: A hand-edited `question:`, or a submodule name, holding a line break or ESC: it is printed raw in a finding, and can forge a line.
- #386: A hand-edited plan field of the wrong type (`pins:`, `paths:`, `legs:`, `source:`): `check` and `execute` crash, and `pins: openGlass` adopts with one-letter pins.
- #388: A source symlink whose target begins with a NUL byte: `check` passes, and `execute` fails after both legs exist, with nothing on stderr.
- #389: Verification never checks the root manifest itself. Only `check`'s refusal of a plan that keeps the source's own `project.yaml` in the root (#305) stands between such a plan and `adoption verified`. Once #305 is fixed, no input reaches the gap through `execute`.
- #417: A relative submodule URL under `--local-remote-dir`: `check` and `execute` resolve it from different remotes, so one can refuse what the other passes.
- #418: A kept submodule whose URL names no repository: `adoption verified`, then the recursive clone the `NEXT:` line prints fails.
- #420: A branch name git refuses (`~`, `a..b`, `x.lock`): `plan` and `check` pass, and `execute` dies after a leg exists.
- #425: A source whose default branch name is not UTF-8: `plan`, `check` and `execute` end in a `UnicodeDecodeError` traceback.
- #427: An `origin` whose organisation is not ASCII or holds a space: `plan` refuses `unsafe-value: --org`, a flag nobody passed.
- #449: A hand edit that makes a neutral pin's `commit:` and `tree_sha256:` disagree: `adoption verified`, then the root's `validate-pins.py` fails `neutral-pin-digest-mismatch`.
- #451: A `--pin-source` that nothing reads, even a missing path: `plan` (and the scaffold's `--dry-run`) exit 0 without a word.
- A moved or dropped non-ASCII path under `LC_ALL=C PYTHONUTF8=0`: `execute` ends in a `UnicodeEncodeError` traceback after both legs are pushed.
- A kept or dropped name holding a line break, a control character or a byte that is not UTF-8: it reaches the split commit message and the pull request body unspelled.
- A source with its own `single-repository.yaml`: `plan` asks the general top-level YAML question. A dedicated rule (drop or root, defaulting to drop) is planned.
- A source branch that differs from the split branch only by letter case, on macOS or Windows: `check` passes, and `execute` fails after both legs exist.
- A name holding a backtick or a double quote, or wrapped in backticks: its spelled form can name another entry, or make the plan unreadable.
- A path policy whose `question:` or rule id holds control characters: `plan`'s terminal report prints them raw.
- A hand-edited `tracking_branch:` or `adopt_branch:` such as `a=b`: `check` says `plan ok`, and `execute` refuses `unsafe-value` before any leg exists.
- A hand-edited plan with a bad `id:` or `org:` beside a bad leg path: `check` and `execute` name different problems first. No leg is made either way.
- A project adopted with a `--spec-path` other than `spec`: the root Makefile still exports `CONTRACTS_DIR ?= $(CURDIR)/spec/contracts`, so the code leg's tooling points at a directory that does not exist.
- On Windows, a source path holding a character NTFS refuses (a TAB, a control character): it cannot be checked out there, so adopting it is untested on Windows.
- On Windows, a source path that is not UTF-8: it cannot be created there, so adopting it is untested on Windows.
- On Windows, a source tree name holding a newline, a TAB or a backslash: its submodule plan is untested on Windows.
- On Windows, a source that tracks symlinks, without `core.symlinks=true`: the links check out as plain files, so adopting it is untested on Windows.

### [update-shape.py and bump-leg.py](https://github.com/opensoft/openRepoShape/issues/458)

- #286: A symlink the root keeps at a pinned path: `apply` writes the standard's bytes through it, possibly outside the root, and exits 0.
- #422: A pinned file kept as a hard link: `apply` rewrites it through its other name, which may lie outside the root.
- #423: A file name that is not UTF-8 under `core.quotePath=false`: `bump-leg.py`, the scaffold and `family.py init` end in a `UnicodeDecodeError` traceback, not a refusal or warning.
- #428: An `apply` whose rollback cannot put one file back (an unwritable copy, a full disk): an `OSError` traceback, with the remaining files left unrestored.
- #431: `apply --branch` started from a directory git cannot open: a good branch name is refused as `update-branch-invalid`.
- #437: A trailing comment on the pin's `files:` or the manifest's `shape:` line: `apply` refuses `update-pin-unrecognised` or `update-manifest-no-shape`, though `check` sent you there.
- #438: A leg pin written as `digests: {tree_sha256: …}`: `bump-leg.py --dry-run` exits 0, and the real run refuses `bump-leg-pin-unrecognised`.
- `bump-leg.py --to` an annotated tag's own id: the dry run shows the tag id and exits 0, while the real run is refused and rolled back with exit 2.
- A locally edited `scripts/repo_shape.py` kept with `apply --accept-local` while taking the new `bootstrap.py`: `make bootstrap` ends in an `ImportError`, though `apply`'s validators pass and `check` then reads everything unchanged.

### [setup, scaffold, family and the shared helpers](https://github.com/opensoft/openRepoShape/issues/459)

- #259: A project id, tracking branch or leg path that YAML reads as another type (`007`, `2026`, `true`): the scaffold and `adopt-project.py` refuse it, because the templates write eight placeholders unquoted, so a numeric branch name cannot be used.
- #275: Two neutral products whose names differ only in `-`, `_` or `.`: they share one `SHAPE_PIN_SOURCE_` variable, and one gets a `neutral-pin-source-unreadable` finding.
- #322: A non-ASCII `--trailer` under the C locale, on a git without `commit --trailer`: the trailer is committed with `?` for each byte.
- #324: `--tracking-branch trunk` in an organisation whose ruleset refuses the push: the printed hint names `main`, and targets the wrong base.
- #338: A `--link-source` path holding `=`, or a mistyped key: the link is skipped in silence, and a source that cannot be entered crashes the naming check.
- #339: A `--pin-source` that does not exist, is a file or cannot be entered: the scaffold ends in a traceback, `--dry-run` included.
- #359: A workflow file that is not UTF-8: the project's `validate-pins.py` ends in a `UnicodeDecodeError` traceback.
- #362: A holder index holding `Members/…`, a case variant of `members/`, on macOS or Windows: `family.py add` cannot add any member.
- #363: An uncommitted `git rm -r Members` on macOS or Windows: `add` commits the gitlink as `Members/<P>`, and fresh clones leave the member empty.
- #364: An untracked `Members/<P>` directory: refused `member-path-taken` on macOS and Windows, but mounted beside it on Linux.
- #392: A flow collection with an empty entry or a leading `:`, `#`, `- ` or `? ` (`[,a]`, `[:]`): the YAML reader accepts it, and reads `[a: b]` as a string.
- #393: A plain value that opens with `]`, `}`, `,`, `@`, a backtick or `%`: the YAML reader takes it as text, where YAML refuses it.
- #407: An uncommitted deletion of the holder's `.gitmodules`: `family.py remove` commits it with the member, and fresh clones leave every member empty.
- #421: `--tracking-branch +x`: `--dry-run` passes, and the push fails after every remote exists.
- #426: A `git config user.name` that is not UTF-8, with no `--created-by`: `family.py init` ends in a `UnicodeDecodeError` traceback.
- #433: A `--local-remote-dir` path that is not UTF-8: the scaffold and `family.py init` end in a traceback after the bare remotes exist.
- #434: A `.github/workflows/` directory the user cannot list: `validate-pins.py` ends in a `PermissionError` traceback.
- #441: A bare `--link-source <path>` in a chain of three or more links: one tree answers for two links, and a correct chain is reported broken.
- #442: An empty path, as in `--link-source openXdox=` or `--pin-source openXdox=`: the current directory is read, and a correct chain is reported broken.
- #443: A scalar (`5`, `openXdox`) where `neutral_product_pins:` or `referent_chain:` should be a list: the validators crash, or read it one letter at a time.
- #444: Product names that fold differently (`openß`, `openss`): the chain readers treat them as one product, and the pin validator as two.
- #450: A `--pin-source` path holding a line break or a byte that is not UTF-8: it is written into the pin file as it stands, or the scaffold crashes after all three repositories exist.
- #454: A family `name` holding a lone surrogate, or any run under `PYTHONIOENCODING=ascii`: `make siblings`, `park` and `resume` end in a `UnicodeEncodeError` traceback.
- #455: A lone surrogate or NUL in `tracking_branch` or a leg's `branch:`: `make bootstrap` ends in a traceback, while `validate-manifest.py` says `manifest ok`.
- `family.py bump --to` a commit whose `project.yaml` `id` another row already pins: `bump` commits, and the holder's validator then refuses `member-duplicate-id`.
- An annotated tag's own id: `family.py add --at` pins the commit it tags, while `bump --to` treats it differently. One rule is still to be chosen.
- No git on `PATH`: the shipped `bootstrap.py` scripts end in a `FileNotFoundError` traceback.
- A directory name that is not UTF-8: `validate-repository-naming.py` ends in a `UnicodeEncodeError` or `UnicodeDecodeError` traceback.
- A holder member directory the user cannot enter: `validate-family.py` refuses `git-not-runnable` and says to put git on `PATH`.
- Re-running before the commit, after the `git rm` that `member-gitlink-unnamed` prints: the finding repeats, and the same command then fails.
- A shape-pin `files:` row with no `path:`: the shipped validators report the path `None` as missing, instead of refusing the row.
- A YAML key written twice: the reader keeps the last one without a word.

### [shape-doctor.py](https://github.com/opensoft/openRepoShape/issues/460)

- #342: A `.pth` file in the operator's Python setup that reaches a `repo_shape.py`: the `manifest` row passes for a root that has lost its own copy, and CI then fails.
- #408: A standard whose own `contracts/path-classification.yaml` does not load: a prose remedy is printed as the NEXT command, and zsh runs it.
- #410: A crash of the standard's own naming script, or a directory name that is not UTF-8: the doctor reports `INVALID (naming)` about the project.
- #413: A leg or member whose detached HEAD holds the only copy of a commit: pasting the `legs` or `members` NEXT moves it, so only the reflog keeps the commit.
- #414: A mount with no `.git`, an unborn HEAD, no `.gitmodules` section, or a pin that is not 40 hex: the `legs` NEXT is the wrong command, or leaves the row red.
- #432: A family member URL in `.gitmodules` that is not UTF-8: the doctor ends in a traceback with no verdict.
- #439: A registered-kind file at a path no check reads (such as `contracts/project.yaml` in an assembly root): the doctor counts it validated and answers `COMPLIANT`.
- #447: A validator killed by a signal, or one that exits with nothing printed: the doctor reports a finding about the project, not a crash.
- #448: A `WARNING` from the project's own `validate-manifest.py`, such as an unreachable referent chain: the `manifest` row says `ok`, and the warning is not shown.

### [The test suite, CI and the docs](https://github.com/opensoft/openRepoShape/issues/461)
