# openRepoShape v1.0.0

openRepoShape v1.0.0 is the first release: core flows, all OSes. Every procedure
in `AGENTS.md` works end to end for ordinary repositories on Linux, macOS and
Windows, and what it does not do yet is listed below as a known limit. The shape
confers nothing, as `AGENTS.md` says: electing it, or membership of a family,
changes no gate, no floor, no grant and no clearance eligibility, and a
one-repository project in no family is reviewed identically. The Triad (an
assembly root with a spec leg and a code leg) is the preferred shape, and
preferred is not required.

## What works

Each line is one procedure of `AGENTS.md`, with the command it runs as
`AGENTS.md` spells it. `AGENTS.md` says where the human's explicit yes comes in.

- **Scaffold a new project:** `curl -fsSL https://raw.githubusercontent.com/opensoft/openRepoShape/main/setup.sh | bash -s -- --org <org> --project <Project> --visibility <private|public|internal> --elected-by '<Name>'`, or `openRepoShape <Project> --org <org> --visibility <…> --elected-by '<Name>'` once the command is installed, or `py setup-project.py <Project> --org <org> --visibility <…> --elected-by '<Name>'` on Windows without WSL2.
- **Adopt an existing repository, including one with no code or no spec:** `./adopt-project.py plan --source <org/repo|path> --project <Project>`, then `./adopt-project.py check --plan adoption-plan.yaml`, then `./adopt-project.py execute --plan adoption-plan.yaml --yes`; a repository with no code yet adds `--allow-empty-leg code` to `plan`.
- **Scaffold a project that declares descent:** `./scaffold-project.py --org MedxSoft --project MedxGlass --pin openGlass@<40 hex commit>`.
- **Check compliance with the doctor:** `openRepoShape --doctor [<path>]`, or `./shape-doctor.py --root <path>` from a checkout.
- **Update a project's shape:** `./update-shape.py check --root <path-to-the-project>`, then `./update-shape.py apply --root <path> --at <commit> --yes --branch shape/update-<sha>`.
- **Advance a leg:** `python3 scripts/bump-leg.py --root <path> --leg spec --to <40 hex> --dry-run`, then the same command without `--dry-run`.
- **Create a family and add a member:** `python3 scripts/family.py init --org <org> --family <Name> [--reuse-empty-repo]`, then `python3 scripts/family.py add  --family-root <path> --member <org>/<Project>`.
- **Park and resume:** `make park ARGS=--dry-run`, then `make park`; on the other machine `make bootstrap && make resume`.

## Verified on

The release commit is `[[RELEASE-COMMIT]]`. The tag waits for the full test run to
pass on all three operating systems on that commit: the CI jobs `tests` (Linux),
`tests-macos` and `tests-windows` all green.

## Known limits

A known limit is a case that only unusual input or setup reaches: bytes that are
not UTF-8, the C locale, control characters, hand-edited YAML, symlink tricks, or
names that differ only by case. Each stays open as an issue, or as a checklist item on its
area's tracking issue (#457 to #461), and is worked when a later release takes it
in. Each line says who can meet it and what they see, and ends with its link.

### adopt-project.py (#457)

- A source that keeps a symlink at or above a path the shape writes (such as `.github` pointing at a missing or outside directory) passes `check`, and `execute` then fails or writes the shape's files outside the assembly after both legs are pushed (#178).
- A source holding a file or directory named `null`, `true` or `false` gets a plan that writes the name unquoted, so `check` finds the path in no entry and an entry that covers nothing until the plan is fixed by hand (#181).
- A source that keeps a symlink in the root at a path the shape writes into (a link to anywhere on disk, or a link loop) has the shape's files written through the link, or ends in a traceback, after both legs are pushed (#183).
- A source whose submodule is kept in a leg leaves the adopted project recording nothing about which leg a person chose for it, so the doctor can only note its placement and cannot verify it (#189).
- A hand-edited plan whose `follow_ups:` is not a list (`5`, `true`) ends `check` in a `TypeError` traceback, and ends `execute` in the same one after both legs are created and pushed (#293).
- A source holding a symlink with an empty target passes `check`, and `execute` creates both legs and then fails cloning the source with exit 2 and nothing on stderr, or, with `core.symlinks=false`, says `adoption verified` over a tree no clone with symlinks on can check out (#303).
- A hand-edited plan whose `question:` or a submodule name holds a line break or ESC has it printed raw in a finding, so it can forge a finding line or reach the terminal as an escape sequence (#328).
- A hand-edited plan whose `pins:`, `allow_empty_legs:`, `paths:`, `legs:` or `source:` has the wrong type ends `check` and `execute` in a `TypeError` or `AttributeError` traceback, and `pins: openGlass` (text where a list belongs) passes `check` and is written as one-letter neutral-product pins (#386).
- A source holding a symlink whose target begins with a NUL byte passes `check`, and `execute` creates both legs and then fails cloning the source with exit 2 and nothing on stderr (#388).
- A source's own `project.yaml` kept in the root is never checked by the final verification for being the shape's manifest, so a plan that gets past the check that refuses it ends `adoption verified` over an assembly the doctor calls NOT A SHAPE ROOT (#389).
- Under `execute --local-remote-dir` (the test path), a kept submodule with a relative url is judged from the bare repositories `execute` creates, but `check` takes no such flag and judges it from GitHub's remotes, so `check` refuses an adoption `execute` verifies and passes one `execute` refuses (#417).
- A kept submodule whose url names no repository (a relative url that resolves alike from the source and the leg, or an absolute one) is `adoption verified`, and then the recursive clone its `NEXT:` line prints fails (#418).
- A hand-edited plan whose branch name git refuses (`~`, `a..b`, `x.lock`, a trailing `/`) passes `plan` and `check`, and `execute` dies at the first git command that takes it after a leg repository exists, so the corrected plan is then refused `leg-remote-exists` (#420).
- A source whose HEAD names a branch that is not UTF-8 ends `plan`, `check` and `execute` in a `UnicodeDecodeError` traceback, exit 1, with no refusal naming the branch (#425).
- A source whose `origin` url has an organisation that is not ASCII or holds a space gets `plan` refused as `unsafe-value: --org`, a flag nobody passed (#427).
- A hand edit that makes a neutral pin's `commit:` and `tree_sha256:` disagree in the plan passes `check`, is `adoption verified`, and then the adopted root's own `validate-pins.py` exits 1 with `neutral-pin-digest-mismatch` on its first run (#449).
- Under `LC_ALL=C PYTHONUTF8=0`, a moved or dropped path that is not ASCII passes `plan` and `check`, both legs are pushed, and `execute` then ends in a `UnicodeEncodeError` traceback (#457 checklist).
- A moved or dropped path holding a line feed, a trailing carriage return, ESC, a tab or a byte that is not UTF-8 reaches the split commit's message and the pull request body unspelled, as another path or as raw control bytes (#457 checklist).
- A source with its own `single-repository.yaml` gets the general `ambiguous-top-level-yaml` question from `plan`, not a rule that names the file and defaults to drop (#457 checklist).
- On macOS or Windows, a source branch that differs from the split branch only by letter case passes `check`, and `execute` makes both legs before git refuses (#457 checklist).
- A source path holding a backtick or a double quote is printed in a spelled form that, copied into the plan, names another entry or makes the plan unreadable (#457 checklist).
- A source path that begins and ends with a backtick prints exactly as another name's spelled form, so `plan`'s table can show two names as one (#457 checklist).
- A path policy whose `question:` or rule `id` holds control characters has them printed as they are in `plan`'s terminal report (#457 checklist).
- A hand-edited plan whose `tracking_branch:` or `adopt_branch:` is a name git accepts but `execute` refuses (`a=b`, `a,b`) says `plan ok` from `check`, and `execute` then refuses `unsafe-value` before any leg exists (#457 checklist).
- A hand-edited plan with a bad `id:` or `org:` beside a bad leg path gets a different first problem named by `check` (`plan-bad-id`) than by `execute` (`plan-bad-leg-path`), though no leg is made either way (#457 checklist).

### update-shape.py and bump-leg.py (#458)

- A project that keeps a pinned copy, `contracts/shape-pin.yaml` or its manifest as a symlink has the standard's bytes written through the link by `apply`, outside the root if that is where it points, with exit 0, and `--branch` reports a commit that does not hold the file (#286).
- A pinned copy, the shape pin or the manifest kept as a hard link is rewritten by `apply` through its other name, a file outside the root that no `check` showed and no pin covers, while the README alone is refused (#422).
- A file name that is not UTF-8 in a repository with `core.quotePath=false` ends `bump-leg.py` in a `UnicodeDecodeError` traceback where it owes `bump-leg-root-dirty`, and the scaffold and `family.py init` in the same way where they owe a warning that the standard's checkout is dirty (#423).
- An `apply` that fails after its first write and then cannot put a file back (a copy that became unwritable, a full disk, a lock) ends in an `OSError` traceback, with the refusal that started the rollback lost and the remaining files not restored (#428).
- Running `apply --branch` from a directory git cannot open (a `.git` file naming a missing gitdir, a malformed `.git/config`, a directory removed under the shell) is refused `update-branch-invalid` for a good branch name (#431).
- A trailing comment on the pin's `files:` line or the manifest's `shape:` line sends `apply` to refuse `update-pin-unrecognised` or `update-manifest-no-shape` after `check` has sent the person there (#437).
- A leg pin written as `digests: {tree_sha256: ...}` gets a `bump-leg.py --dry-run` that prints `old -> new` and exits 0, and a real run that exits 2 with `bump-leg-pin-unrecognised` (#438).
- `bump-leg.py --to` an annotated tag's own id previews the tag's id as the new commit and exits 0 under `--dry-run`, while the real run is refused only by the validators after the rewrite, rolled back, exit 2 (#458 checklist).
- A project that keeps a locally edited `scripts/repo_shape.py` with `apply --accept-local scripts/repo_shape.py` while taking the new `bootstrap.py` gets an `ImportError` from `scripts/bootstrap.py`, `--help` and `make bootstrap`, though `apply`'s validators pass and the project's CI never runs bootstrap (#458 checklist).

### Setup, scaffold, family and the shared helpers (#459)

- A project id, tracking branch or leg path that YAML reads as another type (`007`, `2026`, `true`, `null`) is refused by the scaffold and `adopt-project.py`, because the templates write eight text placeholders unquoted, so a numeric branch name cannot be used (#259).
- A project that pins two neutral products whose names differ only by `-`, `_` or `.` (`open-glass`, `open_glass`) shares one `SHAPE_PIN_SOURCE_` variable between them, and `validate-pins.py` reports `neutral-pin-source-unreadable` (exit 1) for whichever one the variable does not name (#275).
- On a git without `commit --trailer`, a non-ASCII `--trailer` under `LC_ALL=C PYTHONUTF8=0` is committed with a `?` for each undecodable byte, so `José` becomes `Jos??` (#322).
- `--tracking-branch trunk` in an organisation whose ruleset refuses the first push gets a hint that names `main` as the local branch and as `--base`, which the work clone does not have and the pull request cannot use (#324).
- A `--link-source` path under a directory named `a=b`, or behind a mistyped key, is skipped in silence (`declared-unverified`, exit 0), and a source this user cannot enter ends the naming check in a `PermissionError` traceback (#338).
- A `--pin-source` that does not exist, is a file, or lies under a directory this user cannot enter ends the scaffold, `--dry-run` included, in a `FileNotFoundError`, `NotADirectoryError` or `PermissionError` traceback, exit 1 (#339).
- A workflow file in a project's `.github/workflows/` that is not UTF-8 ends `validate-pins.py` in a `UnicodeDecodeError` traceback, exit 1, with no refusal naming the file (#359).
- On macOS or Windows, a family holder whose index holds a path under a case variant of `members/` (such as `Members/README`) cannot take any member with `family.py add`, and the remedy it prints fails the same way every time (#362).
- On macOS or Windows, `family.py add` over an uncommitted `git rm -r Members` commits the member's gitlink as `Members/<P>` while `.gitmodules` and `family.yaml` say `members/<P>`, so every fresh clone of the pushed holder leaves the member's directory empty (#363).
- An untracked `Members/<P>` directory is refused `member-path-taken` on macOS and Windows but let through on Linux, where `add` mounts `members/<P>` beside it, and once it is committed a clone on a case-insensitive disk can add no other member (#364).
- A flow collection with an empty entry or an entry opening with `:`, `#`, `- ` or `? ` (`[,a]`, `[:]`, `[a: b]`) is read by the shared YAML reader where YAML refuses it, and `[a: b]` comes back as the string `a: b` (#392).
- A plain value that opens with `]`, `}`, `,`, `@`, a backtick or `%` is read by the shared YAML reader as text where YAML refuses it (#393).
- `family.py remove` in a holder whose `.gitmodules` was deleted in the work tree and not committed commits that deletion with the member's removal, so every other member's section leaves HEAD and a recursive clone of the pushed holder leaves each remaining member's directory empty (#407).
- `--tracking-branch +x`, a name `git check-ref-format --branch` accepts, passes the scaffold's and `family.py init`'s `--dry-run` and then dies at the push after every remote exists, because a leading `+` in a refspec means force (#421).
- A `git config user.name` that is not UTF-8, with no `--created-by`, ends `family.py init`, `--dry-run` included, in a `UnicodeDecodeError` traceback, exit 1, naming neither the git setting nor the flag that avoids it (#426).
- A directory this user cannot search, on Python 3.14, reads as absent to every `is_file()` and `is_dir()` guard in the shipped tools, so `validate-pins.py` skips its workflow check, `update-shape.py` says `copy-missing`, the doctor says DRIFTED, and other tools skip or misreport instead of refusing by name (#430).
- A `--local-remote-dir` under a directory whose name is not UTF-8 ends the scaffold and `family.py init` in a `UnicodeEncodeError` traceback, exit 1, after the bare remotes exist, though `--dry-run` exits 0 (#433).
- A `.github/workflows` directory this user cannot list ends `validate-pins.py` in a `PermissionError` traceback, exit 1 (#434).
- A bare `--link-source <path>` in a chain of three or more links answers for every link that has no more specific source, so a correct chain is reported broken, a FINDING with exit 1 (#441).
- An empty path in `--link-source openXdox=` or `--pin-source openXdox=` reads as the current directory, so run from a project root the naming gate reads the project's own `project.yaml` as the link's declaration and reports a correct chain broken (#442).
- A scalar (`5`, `true`, `openXdox`) where `neutral_product_pins:` or a leg's `naming.referent_chain:` should hold a list ends the validators in a `TypeError` traceback, so `make validate` stops at its first command, or has the naming gate read the scalar one letter at a time and exit 0 (#443).
- Neutral products whose names fold differently (`openß` and `openss`) are one link to the chain readers and two products to the pin validator, so a holder's tree that declares one can verify a chain that names the other (#444).
- A `--pin-source` clone at a path holding a line break is written as it stands into the new pin file, with a line of the path's choosing, and one at a path that is not UTF-8 creates all three repositories and then ends the scaffold in a `UnicodeEncodeError` traceback, exit 1 (#450).
- A `--pin-source` that nothing reads (no `--pin`, or no `--referent-chain` link), even a path that does not exist, is accepted by `scaffold-project.py --dry-run` with exit 0 and no word, where the root's own `validate-pins.py` notes such a value (#451).
- A family whose `name` holds a lone surrogate, or any run under `PYTHONIOENCODING=ascii`, ends `make siblings`, `make park` and `make resume` in a `UnicodeEncodeError` traceback (#454).
- A lone surrogate or NUL in `tracking_branch` (or a leg's `branch:`) ends `make bootstrap` in a subprocess traceback in step (a) while `validate-manifest.py` says `manifest ok`, so no tool names it (#455).
- `family.py bump --to` a commit whose `project.yaml` records an `id` another row already pins commits a holder that its own `validate-family.py` then refuses as `member-duplicate-id`, where `add` refuses it first (#459 checklist).
- `family.py add --at` an annotated tag's own id pins the commit the tag names, while `bump --to` refuses the same id and the two word a tag of a tree differently, because one rule is still to be chosen (#459 checklist).
- With git not on PATH, both roots' `scripts/bootstrap.py` end in a `FileNotFoundError` traceback, exit 1, instead of saying git is missing (#459 checklist).
- `scripts/validate-repository-naming.py` ends in a `UnicodeEncodeError` (`--explain` and the plain listing under a strict UTF-8 stdout, which the doctor gives its children) or a `UnicodeDecodeError` (a name read from stdin) on a directory name that is not UTF-8, while `--quiet` answers `FINDING naming-unclassified` for the same name (#459 checklist).
- `validate-pins.py` and `validate-family.py` use two rules for `git-not-runnable`: with git on PATH, a holder whose `members/<P>` this user cannot enter is refused `git-not-runnable` and told to put git on PATH, while a project's gate ends in a `PermissionError` traceback, exit 1, on a leg directory it cannot enter (#459 checklist).
- After the `git rm` that `member-gitlink-unnamed` prints and before the commit, a re-run of `validate-family.py` prints the same finding again, and the same command then dies with "pathspec ... did not match any files" (#459 checklist).
- A shape pin `files:` row that is a mapping with no `path:`, or with `path: ""`, is refused by `update-shape.py` and the doctor as `update-pin-row`, while the shipped validators read the path as `None` and print `shape-copy-missing: ... None is pinned but absent` instead of refusing the row by name (#459 checklist).
- A key written twice in a contract file (a duplicated `commit:` or `members:`) passes the shared YAML reader without a word, which keeps the last (#459 checklist).
- The helpers that ask a template's own YAML reader and validator about a manifest's values exist twice, in `scripts/shape_materialize.py` for `project.yaml` and in `scripts/family.py` for `family.yaml`, so a maintainer who changes one must change the other (#459 checklist).

### shape-doctor.py (#460)

- A `.pth` file in the operator's user site or a virtualenv that names a directory holding a `repo_shape.py` stands in for the copy a root lost, so the `manifest` row says `ok ... passes` for a gate that fails in CI on `ModuleNotFoundError` (#342).
- A standard whose own `contracts/path-classification.yaml` does not load gets a row whose NEXT is a paragraph of prose, which `sh` and `bash` reject and zsh (macOS's default shell) runs, executing `git submodule update --init --recursive` and `python3 scripts/validate-pins.py` in the reader's directory (#408).
- A crash of the standard's own `validate-repository-naming.py`, or a directory whose name is not UTF-8, is reported by the `naming` rows as a FINDING about the project (`INVALID (naming)`, exit 1) with the script's traceback quoted as a fact about the name, because they read only the exit code (#410).
- A leg or member whose detached HEAD holds the only copy of a commit (an emptied mount whose kept gitdir holds it, a commit made in a holder's pinned `members/<P>`, or one in a member's own leg that `--recursive` moves) has HEAD moved by the pasted `legs` or `members` NEXT with no reflog note, so only a reflog entry keeps the commit (#413).
- A mount with no `.git` but its gitdir kept, an unborn HEAD, an empty mount with no `.gitmodules` section, or an empty mount whose pin is not 40 hex gets a `legs` NEXT that is the wrong command: a gate that says `pins ok` while the row stays red, a git line that exits 128, or no instruction to run the doctor again (#414).
- A family holder whose `.gitmodules` holds a member url that is not UTF-8 ends `shape-doctor.py --root` in a `UnicodeDecodeError` traceback, exit 1, with no verdict (#432).
- A file that declares a registered kind at a path no check reads (`contracts/project.yaml` in an assembly root, `contracts/family.yaml` or `contracts/spec-pin.yaml` in a family holder, or a `contracts/<x>-pin.yaml` no leg or declared descent names) is counted `ok` by `manifest kinds` and the verdict is COMPLIANT though nothing reads it (#439).
- A validator killed by a signal (a negative exit) or one that leaves by `os._exit(1)` with nothing printed is read by the doctor as reporting a finding about the project, not as a crash, so a root's own gate ended by the OOM killer or a timeout is a FINDING (#447).
- A project's own `validate-manifest.py` that exits 0 after printing `WARNING naming-referent-chain: ... not reachable here` gets a `manifest` row that says `ok ... passes`, and the warning appears nowhere in the text or `--json` report, so a referent chain nothing on this disk could check reads as checked under COMPLIANT (#448).
- A shape pin and a pinned copy that are both conflicted (an `update-shape.py apply --branch` pull request beside a branch that kept an edit with `apply --accept-local`, or two applies to different targets) get a `shape currency` NEXT of `git checkout --ours -- <copies> contracts/shape-pin.yaml`, which with the update side as ours drops the person's lines from the copy and is then called COMPLIANT, exit 0 (#460 checklist).

### The test suite, CI and the docs (#461)

- No test runs the PowerShell form of the doctor's `legs` NEXT git line, and the test that its explanation holds none of `;`, `'`, a backtick or a parenthesis passes only because pytest's temporary roots need no quoting, so a Windows root whose path holds a space is untested (#415).
- A reader who looks up `update-shape.py apply --add`'s refusals in `README.md` or `docs/handbook.html` finds neither `update-add-symlink` nor `update-add-not-a-directory` named (#429).
- About a dozen test fixtures (in `tests/test_update_shape.py`, `tests/test_doctor_validator_rows.py`, `tests/test_family.py` and the adopt and scaffold fixtures) and `templates/family-root/scripts/siblings.py` still clone a just-pushed local remote by plain path, which can race git's background maintenance on the macOS runner, though none has failed in CI (#461 checklist).
- `tests/test_shape_pin_files_not_a_list.py` accepts the doctor's exit 3 (CANNOT ANSWER) as well as exit 1 (INVALID) for a root pin that cannot be read, and its docstring still calls that verdict someone else's to move, so a doctor that answered CANNOT ANSWER for `files: abc`, a quoted string or a mapping would still pass it (#461 checklist).
- `tests/test_shape_doctor.py` and `tests/test_windows_paths.py` load the family template's `bootstrap.py` and `siblings.py` with `spec.loader.exec_module`, which writes `.pyc` files into the template tree, so a test that reads every file there passes or fails by test order (#461 checklist).

## Upgrading a project

A project holds copies of the shape's files, so an upstream fix reaches it only
when someone updates it. `AGENTS.md`'s "Updating a project's shape" is the
procedure: run `update-shape.py check` first, which writes nothing, and run
`update-shape.py apply` only on the human's explicit yes, landing the result as a
pull request. This release adds no other upgrade step.
