# openRepoShape v1.0.1

v1.0.1 is v1.0.0 plus one change: openRepoShape installs in one line, and the
command it installs stays on the release it was installed from (#564).

## What 1.0.1 adds

- **The one-line install.** `install.sh` is attached to every release, so
  this line always installs the newest one:

  ```sh
  curl -fsSL https://github.com/opensoft/openRepoShape/releases/latest/download/install.sh | bash
  ```

  It reads which release is the newest from github.com's `releases/latest`
  redirect, with no `gh` and no login. It fetches that release's
  `openRepoShape` and installs it into `~/.local/bin`, or
  `$OPENREPOSHAPE_BIN_DIR`, pinned to the release. It installs
  `git-filter-repo` 2.47.0 with `pipx` when `pipx` is there and
  `git-filter-repo` is not, and otherwise prints the one command that
  installs it. It ends with `openRepoShape --preflight`. It never runs `sudo`
  and installs nothing else. It exits 0 when the command is installed and the
  preflight passed, 1 when the command is installed but the preflight did not
  pass or the command does not stay on the release, and 2 when it installed
  nothing.
- **An installed command that stays on its release.** `openRepoShape
  --install` records the ref it runs at, `$OPENREPOSHAPE_REF`, in
  `openRepoShape.ref` beside the command it places. The installed command then
  fetches `setup.sh` at that ref, `setup.sh` clones the standard at it
  (`--shape-ref`), and `--doctor` checks its clone out at it. In v1.0.0 an
  installed command fetched main on every run unless `$OPENREPOSHAPE_REF` was
  exported. `$OPENREPOSHAPE_REF` set for one run still overrides the record,
  and `openRepoShape --version` prints the ref in force. An install with no
  ref records nothing, removes any record already there, and follows main. The
  installed command is byte for byte the release's own file.

## Install and upgrade

- **The newest release:** the line above. Run it again to upgrade to the
  newest release.
- **A named release:**
  `curl -fsSL https://github.com/opensoft/openRepoShape/releases/latest/download/install.sh | bash -s -- v1.0.1`,
  or `bash install.sh v1.0.1` from a checkout or a download.
- **What is installed:** `openRepoShape --version` prints
  `openRepoShape (opensoft/openRepoShape @ v1.0.1)`.
- **By hand, at main:** the README's
  `gh api repos/opensoft/openRepoShape/contents/openRepoShape … | bash -s -- --install`
  line still installs main's command, which records no ref and follows main.
- **Windows:** `install.sh` is bash, for macOS, Linux and WSL2. Native
  Windows still starts with `py setup-project.py`, as the README says.
- **A project's pin** on the standard works as before. Follow
  [How to pin 1.0.0](v1.0.0.md#how-to-pin-100) with the v1.0.1 release
  commit.

## A script that runs `--install`

A script that runs `openRepoShape --install` with `$OPENREPOSHAPE_REF`
exported now pins the installed command to that value. If the value is not a
ref the command should run, unset it for the install. To keep the command on a
commit or a tag, set it to that commit or tag.
