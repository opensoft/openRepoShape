v1.1.1 is a patch of v1.1.0. It adds no command and no flag. It fixes text
that a terminal acts on reaching it, names that are not ASCII or not UTF-8,
`.gitmodules` files read otherwise than git reads them, and adoptions that
failed late, after the plan was built or a leg was made. It changes pinned
shape copies, so a project or a family holder takes those fixes into its
own gates by `update-shape.py` (below). It is cut from `release/v1.1`
(#850).

## What 1.1.1 fixes

- **Text a terminal acts on stays off it.** `install.sh` and the bash
  `openRepoShape` refuse a `$OPENREPOSHAPE_BIN_DIR` holding a control
  character, a C1 control included, or one of 41 characters a terminal
  draws as something other than itself (a bidi control, a character of no
  width, a soft hyphen, U+2028, U+2029), before any request and without
  echoing it (#760, #837), and read a name the bytes refuse again in a
  multibyte locale's own charset, so that locale's letters are placed
  (#858). The command checks `$OPENREPOSHAPE_REPO` and `$OPENREPOSHAPE_REF`
  the same way before `--version` answers (#866).
  `validate-pins.py`, `family.py init`, `scaffold-project.py` and
  `bump-leg.py` spell the names and paths they print (#712, #766).
- **Names that are not ASCII, or not UTF-8.** The doctor prints such a path
  as itself, or escaped whole where the report cannot hold it, so a line
  naming it runs as printed (#785), and it finds a member whose `.gitmodules`
  section name is not UTF-8 (#732). `make bootstrap` moves back a leg whose
  upstream is not UTF-8 (#710); `update-shape.py`, `family.py` and
  `bump-leg.py` read the branch HEAD is on as git's bytes (#765);
  `setup-project.py` and a project's `bootstrap.py` tell each Python child
  the encoding it is read in (#836); and a byte-order mark no longer breaks
  a YAML file or the upstream notice (#855).
- **`.gitmodules`, read as git reads it.** The doctor, `make siblings` and
  both `validate.yml` templates read the sections, keys and values git
  reads, so none of them names a url, a NEXT line, a clone or an App-token
  repository that git would not (#733, #741, #786). A holder's
  `make bootstrap` and its `validate-family.py` name a value that git dies
  on, where bootstrap said `family bootstrap ok` (#768).
- **`adopt-project.py` asks before it makes anything.** `--source`, `--out`,
  `--pin-source`, the source's default branch and both leg repositories are
  asked about before any leg exists, and refused by name (#796, #799, #800,
  #797, #798). `check` holds a plan to the repository it records (#716),
  the line-ending block governs a copy written through a symlinked
  directory (#807), and the recorded answers cover a directory split by
  hand (#801).
- **One reading of `legs:` and of a branch name.** A `legs:` that is not a
  list, or an entry that is not a mapping, is said in one sentence by every
  gate and reader (#714, #832). The YAML reader keeps Unicode spaces as
  text, and a branch name holding a character that does not print or is
  white space is refused (#715).
- **Git Bash gets `sh`'s quoting.** Under Git Bash, the lines the tools
  quote for the host are quoted for `sh`, where they were quoted for
  PowerShell (#711).
- **Family holders.** `family.py add`'s and `validate-family.py`'s remedies
  for a member under another spelling type as printed (#761, #762); `add`,
  `bump` and `remove` see a cherry-pick or a revert stopped in a reftable
  holder (#684); and `make siblings` reports a slot that is not a clone and
  places the members after it (#735, #784).
- **CI on a release branch.** `tests.yml` runs on a push to
  `release/v<X.Y>` as on a push to main, and `release.yml`'s header says
  how a fix is back-ported (#852, for #850).

## Install and upgrade

- **The newest release, by the one line:**

  ```sh
  curl -fsSL https://github.com/opensoft/openRepoShape/releases/latest/download/install.sh | bash
  ```

  The same line again upgrades. `… | bash -s -- v1.1.1` names this release.
  `openRepoShape --version` prints `openRepoShape (opensoft/openRepoShape @ v1.1.1)`.
- **From PyPI:** `pipx install openreposhape==1.1.1` for this release, and
  `pipx upgrade openreposhape` to upgrade one already installed.
  `openRepoShape --version` prints
  `openRepoShape 1.1.1 (opensoft/openRepoShape @ <release-commit>)`.
  [v1.1.0's notes](v1.1.0.md#install-and-upgrade) say where `pipx` comes
  from, and that the two installers do not replace each other's command.
- **A project's and a holder's shape copies.** A copied file reaches no
  project by itself. v1.1.1 changes six of the copies an assembly root
  pins: `scripts/validate-pins.py`, `scripts/validate-manifest.py`,
  `scripts/bootstrap.py`, `.github/workflows/validate.yml`,
  `scripts/repo_shape.py` and `scripts/validate-repository-naming.py`. It
  changes six of the copies a family holder pins: `scripts/validate-family.py`,
  `scripts/bootstrap.py`, `scripts/siblings.py`,
  `.github/workflows/validate.yml`, `AGENTS-shape.md` and
  `scripts/repo_shape.py`. From a checkout at the v1.1.1 release commit,
  `update-shape.py check --root <path>` reports each as `upstream-changed`
  in a root pinned at v1.1.0 that has not edited it, and
  `update-shape.py apply --root <path> --at <release-commit> --yes --branch shape/update-<sha>`
  re-copies and re-pins them, on the person's yes, as AGENTS.md's
  "Updating a project's shape" says. Until then the root's own gates and
  `make bootstrap` are v1.1.0's.
- **The rendered READMEs.** A project's or holder's `README.md` is rendered
  once, when it is made, and `update-shape.py apply` rewrites only a
  holder's closing `Shape:` line. So the assembly root's new sentence on a
  `.gitmodules` that git refuses (#790), and the holder's new sentences on
  the one spelling of `members/` and on its folder's name (#738, #822),
  reach new roots only; an existing holder reads the last two in its
  re-pinned `AGENTS-shape.md`.
- **What a script sees.** A holder's `make bootstrap` over a `.gitmodules`
  value that git dies on now fails, exit 1, where it said
  `family bootstrap ok` (#819, #768). `adopt-project.py plan` prints a
  blank line and `plan written to <out>` first, as soon as the plan is on
  disk, and refuses `--out /dev/null` (#833, #799). `openRepoShape --version`
  refuses, exit 2, a `$OPENREPOSHAPE_REPO` or `$OPENREPOSHAPE_REF` holding
  a control character or a character drawn as another (#872, #866).
  `update-shape.py apply --branch` run from a branch whose name is not UTF-8
  is refused, exit 2 (#849, #765).
- **A project's pin** on the standard works as before. Follow
  [How to pin 1.0.0](v1.0.0.md#how-to-pin-100) with the v1.1.1 release
  commit. A scaffold run through the package pins that commit and digest by
  itself.

## What changed since v1.1.0

v1.1.0 was tagged on `190133d` on 2026-10-17. Everything below landed on
main after that commit, by area; `release/v1.1`, which is fast-forwarded to
main after each landing, holds the same commits. The list runs to main
`85555d0`.

### adopt-project.py

- **`--source`, a repository's top level.** A `--source`, or a plan's
  recorded `source.local_path`, that names no repository's top level is
  refused as `source-not-top-level`, naming what was given, before git
  reads anything else in it; the way out is the top level, which
  `git rev-parse --show-toplevel` prints, or its `org/repo`. So a file no
  longer ends in a traceback, and a directory inside a repository no longer
  plans that subtree alone under the repository's name. An empty value and
  an unknown `~user` are `source-unresolvable`, `owner/.git` is refused
  with no `gh` call, `www.github.com` is read as `github.com`, and a source
  that lost a blob is `git-failed`, naming the blob and `git fsck` (#831,
  #796).
- **`--out`, asked first.** `plan` asks whether it can write `--out` before
  it reads or clones the source or makes a work directory, and refuses a
  folder, a pipe or a device, a missing folder or one nobody can write in
  as `adopt-out-unwritable`, where a mistyped `--out` ended in a traceback
  after the whole plan was built. `--out /dev/null`, which exited 0 and
  threw the plan away, is refused too. `plan written to <out>` is printed
  as soon as the plan is on disk, so every plan's stdout now starts with a
  blank line and that line (#833, #799).
- **`--pin-source`, a clone's top level.** `plan` and `scaffold-project.py`,
  `--dry-run` alike, refuse a `--pin-source` that is not a clone's top
  level, or a bare clone's, as `pin-source-not-a-clone`, naming the top
  level git finds. `check` finds such a path in a plan as
  `plan-pin-source-not-a-clone`, before a partial clone's NOTE, and
  `execute` refuses it before any leg. So a folder inside a clone no longer
  records the digest of part of its tree, or of nothing. What a top level
  digests is unchanged, so existing pins stay valid (#842, #800).
- **The source's default branch, by its full name.** `plan`, `check` and
  `execute` read `origin/HEAD` and HEAD by full name and whole, and read the
  source only at a branch of its own, by `refs/heads/<branch>`. A
  `git clone -b` source, whose `origin/HEAD` names a branch with no local
  copy, is read at `--tracking-branch`, or refused
  `source-default-branch-not-local` with ways through that work, where it
  was `git-failed` with no remedy. A HEAD on `main<U+00A0>`, on a local
  branch named `origin/x`, or beside a tag `main` no longer adopts another
  branch's commit, or the tag's. A default branch outside the alphabet,
  such as `café`, is still refused, and the refusal now says the way past it
  (#830, #797).
- **Both leg repositories, asked about first.** `execute` asks about both
  leg repositories, under `--local-remote-dir` or on GitHub with
  `gh repo view`, before it makes either, and refuses everything in their
  way at once, saying that no leg repository was created. A code leg that
  already exists no longer leaves the spec leg made. `check` asks the same,
  so a `--local-remote-dir` that is a file or cannot be written in is a
  finding, where `execute` ended in a traceback after `plan ok`. A `gh` that
  cannot answer is `adopt-remote-unreadable` in `execute`, and a NOTE in
  `check`, which stays usable offline (#861, #798).
- **A plan held to its recorded repository.** `check` prints the
  rename-first remedy for a plan in the source's own name that the naming
  policy refuses, as `execute` does. Where the live source names no
  repository, a plan is held to its own recorded `source: repository:`, so
  a plan for `acme/Atlas` edited to `Atlsa`, with `origin` then removed from
  the source, is `plan-not-the-source` in `check` and `execute` alike, where
  `check` said `plan ok` (#825, #716).
- **The line-ending block, by the path git tracks.** #471's block in a
  split's `.gitattributes` names each pinned copy by the path git tracks it
  at, and again by its pinned path where the two differ, so a copy written
  through a root-kept `.github -> ci` no longer checks out with CRLF under
  `* text=auto eol=crlf` and fails `validate-pins.py` after
  `adoption verified`. `check` reports a nested `ci/.gitattributes` that
  outranks the root's rule as `plan-nested-attributes`, and passes such a
  source under `core.safecrlf=true` (#844, #807).
- **Answers recorded for a hand split.** `execute`'s `answered_paths:` also
  records each plan entry that the doctor's walk of the leg it lands in
  would put in another leg, or leave as a question, so a directory split by
  hand out of an extension-majority fold no longer reads MISPLACED on the
  doctor's first run after `adoption verified`. A plan left as `plan` wrote
  it gets v1.1.0's record, byte for byte (#829, #801).

### update-shape.py, bump-leg.py and a project's own scripts

- **The pins gate, on what it cannot read.** A project's `validate-pins.py`
  refuses by name a pin, the manifest, a shape copy or a leg checkout that
  it cannot reach or open, named relative to the root, once, with advice
  for the cause (`chmod u+r` for a permission, another sentence otherwise),
  where it ended in a `PermissionError` traceback, or on Python 3.14 said a
  present file did not exist. A copy it cannot open is
  `shape-copy-unreadable`, and a leg checkout it cannot search
  `pin-submodule-unreadable`. Every name and path it prints is spelled as
  `repr` spells a character that does not print, so a newline, a bidi
  control or an ESC in a workflow name or a pin entry no longer reaches the
  terminal raw, and `--pin-source openss=` no longer answers for an `openß`
  pin (#827, #712).
- **A `legs:` that is not a list.** In the naming gate, `validate-manifest.py`
  and `validate-pins.py`, a `legs:` that is not a list is the finding
  `manifest-legs`, and an entry that is not a mapping `manifest-leg`, exit 1,
  where `legs: 5` ended in a `TypeError` and a scalar was walked a letter
  at a time. Under `--project` the naming gate never reads stdin, so no
  `legs:` can make it wait, and `--explain` no longer ends in a
  `UnicodeEncodeError` on a name that is not UTF-8. A chain link or a
  declared pin that is not a name is a finding (#826, #714). The doctor, a
  project's `bootstrap.py`, `bump-leg.py` (`bump-leg-manifest-legs`) and
  `update-shape.py` say the same sentences, where each ended in a
  `TypeError` or read the project as one with no legs (#862, #832).
- **The YAML reader, and a branch name that does not print.**
  `repo_shape.py`'s reader strips only YAML's space and tab, so a value
  that a Unicode space opens reads as PyYAML reads it, and `- :`, `: a`,
  `{?: 1}` and `[?: 1]` are refused. `validate-manifest.py`,
  `make bootstrap`, `bump-leg.py` and `update-shape.py` refuse a branch name
  holding a character that does not print or is white space, such as
  `main<U+00A0>`, which the reader used to read as `main`; `bump-leg.py` and
  `update-shape.py` refuse it as `unseen-branch`, before any fetch or write
  (#823, #715).
- **A byte-order mark.** A YAML file, or a `.shape-upstream-tip`, that a
  Windows editor saved with a byte-order mark reads as the text it holds,
  in every reader, the doctor's included: a marked `project.yaml` is no
  longer `schema_version is None`, and the upstream notice names the tip
  (#868, #855).
- **`make bootstrap` and a branch that is not UTF-8.** Step (a) decodes
  git's output as the system decodes a name it is given, so a tracking
  branch whose upstream is not UTF-8 is moved back, where it ended in a
  `UnicodeDecodeError`, and a good branch this system's encoding cannot
  write gets a line of its own, `did not try branch`, where it ended in a
  traceback (#824, #710).
- **`make bootstrap` tells the validators their encoding.** A project's
  `bootstrap.py` starts each validator with the encoding its words are read
  in, so `make bootstrap` passes a project whose `name:` the Windows code
  page cannot hold, where `validate-manifest.py` ended in a
  `UnicodeEncodeError` (#851, #836).
- **The branch HEAD is on, as git's bytes.** `update-shape.py`, `family.py`
  and `bump-leg.py` read the branch HEAD is on as the bytes git wrote, so a
  branch ending in U+00A0, U+2028 or U+0085 is no longer read as its
  neighbour: `family.py remove` no longer prints a push line for the
  neighbour, and `update-shape.py apply` no longer reports a commit and a
  push on it, nor switches HEAD to it in a rollback. A name that is not
  UTF-8 is refused by name before anything is written, as
  `update-branch-not-utf8`, `family-branch-not-utf8` or
  `bump-leg-branch-not-utf8`, with a `git branch -m` remedy (#849, #765).
- **`validate.yml`, reading `.gitmodules`.** Both `validate.yml` templates,
  the assembly root's and the family root's, read each submodule url by its
  exact key, so a section named `members/My IRRS` gives the url git gives,
  where it left that repository out of the App token and listed it wrong
  (#782, #741). Their three url-reading steps read `.gitmodules` by the
  rules the doctor and `siblings.py` read it by: a section git ignores, a
  section with no `path`, a `path` or `url` beginning with `-`, and an
  unmerged file name no repository. A file git refuses whole fails the
  names step and the fetch step with an `::error::` naming the cause,
  whatever credential is set, where the fetch step with no credential went
  green (#790, #786).

### scaffold, setup, family and the shared readers

- **Paths, spelled.** `family.py init`'s `folder` and `landing` rows, seven
  refusals of `family.py` and `scaffold-project.py`, and the `bump-leg.py`
  refusals that name the root, name each path as `shown_path` does, so an
  ESC or a line break in a holder, a folder, a lock, a local remote or a
  root no longer reaches the terminal from them, nor prints a forged line
  (#814, #766).
- **Git Bash's quoting.** Under Git Bash (`MSYSTEM` set), the lines the
  tools quote for the host are quoted for `sh`, not PowerShell, through one
  question, `host_shell_dialect` in `repo_shape.py`: the doctor's lines,
  setup's family lines and `family.py`'s `NEXT`, `switch -c`, `add` and
  `cd` lines paste whole in the shell that printed them, and the doctor
  gives Git Bash `cp` and `env PYTHONPATH=...`, where it gave `Copy-Item`
  and `$env:PYTHONPATH` (#821, #711).
- **setup-project.py's prompt.** A project name typed at the prompt is
  checked as `--project` is, before step (3) builds a path from it, so
  `../x`, `a/b`, `..` and `--help` are refused by name, exit 2, where they
  met an `--id` hint, a help page or a probe folder; an empty line says
  that no name was typed (#756, #729).
- **setup-project.py's children.** Every Python child that setup starts is
  told the encoding it is read in, so a cp1252 stdout gets one encoding
  from setup, where a measured run printed 9 of its 129 lines in cp1252
  among UTF-8 ones (#851, #836).
- **family.py in a reftable holder.** `add`, `bump` and `remove` refuse a
  cherry-pick or a revert stopped in a holder whose refs are a reftable,
  asking its ref store for `CHERRY_PICK_HEAD` and `REVERT_HEAD` by their
  exact names, where they went on to their commit. With #816 in v1.1.0,
  that closes #684 (#846, #684).
- **family.py add's move back.** The move back that `add` prints for a
  member's gitlink under another spelling of its row's path points the
  member's section of `.gitmodules` back too, sets aside first a file or a
  link the index holds in its way, and puts back a member whose removal is
  staged. Its closing `mv` is guarded, moves nothing where nothing is
  there, never moves a checkout and leaves one to delete by hand; the
  update comes last; and `--sparse` is printed where the sparse rules leave
  an entry out, not only where its bit marks it. So no printed line leaves
  a section naming another spelling, or un-registers a member (#828, #761).
- **validate-family.py's remedies.** The wrong-case move back mends
  `.gitmodules`, adds `--sparse` where a sparse checkout needs it, and moves
  aside first an entry in its way. A row's staged removal is a finding
  before the commit that makes it, a section with no url is
  `member-gitmodules-url-absent`, `member-uninitialized` names the gitlink
  where git's init stops and the cure for it, and a pin whose commit the
  member lacks names the fetch, or the `family.py bump`, that cures it
  (#820, #762).
- **A `.gitmodules` value git dies on.** Where `.gitmodules` gives a value
  that git dies on as it reads the file (a key with no value,
  `update = None`, a `shallow` that is no boolean, and more), a holder's
  `make bootstrap` fails, naming the key, where it said
  `family bootstrap ok`, and `validate-family.py` reports
  `gitmodules-value-refused` in every mode, with the line that takes the
  key out. Where the work tree has no `.gitmodules`, bootstrap reads the
  index's, then HEAD's, as git does (#819, #768).
- **`make siblings` and a slot that is not a clone.** A file, a folder that
  `make siblings` cannot list or enter, or a link to nothing at
  `../<Project>` is NOT A CLONE, reported and left as it is, and the members
  after it are placed, where the run ended in a traceback, or the dry run
  said `would clone` where the real run ended `CLONE FAILED`. `make park`
  and `make resume` skip such a member as `SKIPPED no clone`, and the
  doctor's `members` row calls each such slot `not-a-clone`, as
  `make siblings` does (#772, #735; #788, #784).

### shape-doctor.py

- **`.gitmodules`, as git reads it.** The doctor and `make siblings` read
  only what `git submodule init` reads: a section whose name is empty or
  holds a `..` component is skipped, a `path` or `url` beginning with `-` is
  skipped, that key alone, a section with no `path` names no mount, a key
  with no value or a value git dies on gives no url where git refuses the
  file, and an unmerged `.gitmodules` names no url. So neither names a mount
  url, a NEXT line or a clone where git says `No url found` or refuses the
  file (#775, #733).
- **Section names, as git's bytes.** A `.gitmodules` section name keeps
  git's own bytes and is handed back to git as them, so the doctor finds
  the url and the kept git directory of a member named `caf` and the byte
  0xE9, gives its detached commit a keep line under any locale, and no
  longer ends `--root` in a `UnicodeEncodeError` traceback on a name that is
  not ASCII under `LC_ALL=C PYTHONUTF8=0` (#774, #732).
- **Paths that are not ASCII.** The doctor prints such a path as itself in
  every NEXT, keep line and WHY where the report's encoding can write it,
  and escaped whole where it cannot (`$'...'` for `sh`, a `[char]`
  concatenation for PowerShell), where it printed each such character as
  `?`, there and in `--json`. So a line naming a member `café` runs as
  printed, and `--json` is written as UTF-8 whatever stdout holds (#792,
  #785).
- **Conflicted shape pins.** A conflicted shape pin's NEXT takes the side
  whose pin reads, and names no line where no side's pin reads, so running
  it no longer leaves the doctor naming the same NEXT again (#779, #752). A
  shape copy renamed on one side of a merge, conflicted under a name no pin
  lists, is named in the `why` and in `left_for_a_person` as renamed from
  that copy, for a person to merge, and never taken (#781, #753). A copy
  renamed on both sides, `DD` at its old name, is named gone on both sides,
  with each side's new name where that side's own commit proves it, and
  never as a merge of hunks git did not merge (#789, #783).
- **A partial clone of the standard.** The partial-clone row's NEXT fetches
  by id each commit the clone lacks objects at,
  `git -C <shape> fetch --refetch --no-filter <remote> <commit>...`, from a
  promisor remote whose branches hold it, so it no longer loops where the
  pinned commit sits only on another remote or another branch. Its `why`
  says where each commit is, or that the clone does not hold it at all, and
  from git 2.45 a commit the clone does not hold is no longer counted as
  one object lacked (#773, #754).
- **A root that lost `repo_shape.py`.** The `legs` and `members` rows'
  lockstep NEXT is the `git -C <root> checkout HEAD -- scripts/repo_shape.py`
  that the `pins` and `family` rows print, or none where HEAD no longer
  holds the file, where it named the root's own gate, which dies on the
  import (#771, #750).
- **A pin this user cannot read.** The `legs`, `manifest kinds` and
  `shape currency` rows name a pin or a `contracts/` this user cannot read
  in `validate-pins.py`'s words, `cannot be read (Permission denied)`, with
  its advice, and never `git checkout HEAD --`, which discards what the file
  holds. The verdict is `INVALID`, not `DRIFTED` (#860, #847).
- **A `legs:` that is not a list** (#862, #832), above: the `legs`,
  `leg shape files` and `placement` rows are `n/a` and wait on the
  `manifest` row, and `--placement-plan` refuses by name and writes
  nothing.

### Install, CI and the docs

- **`$OPENREPOSHAPE_BIN_DIR` and control characters.** `install.sh` and
  `openRepoShape --install` refuse a `$OPENREPOSHAPE_BIN_DIR` holding a
  control character, a tab, DEL and a C1 control included, in any locale,
  before they name it, exit 2, and `install.sh` refuses one holding `:` too;
  `install.sh` refuses each before any request. `--install` used to place
  the command under such a directory and print a carriage return or an
  escape as typed (#804, #760).
- **Characters a terminal draws as another.** `install.sh` and
  `openRepoShape` refuse a `$OPENREPOSHAPE_BIN_DIR`, `install.sh` a
  repository, a version, an option or a redirect's location, and the
  command a repository or a ref, that holds one of 41 code points,
  `MISDRAWN_CHARACTERS` in the launcher:
  U+00AD, the twelve bidi controls, U+2028, U+2029, and the format
  characters of no width that nothing needs. Each is refused by its code
  point, before any request, and never echoed, where `~/` U+202E
  `.local/bin` could read as another directory. U+200C and U+200D stay
  allowed (#841, #837).
- **A name in a multibyte locale.** Where the bytes refuse a
  `$OPENREPOSHAPE_BIN_DIR`, both files read it again in the locale's own
  charset, as `locale charmap` names it, through `iconv`, so a GB18030, GBK
  or Shift_JIS name that holds no control character and nothing drawn as
  another is placed, a default `$HOME/.local/bin` under such a user name
  among them. Where nothing can read it, the bytes decide as before (#867,
  #858).
- **`$OPENREPOSHAPE_REPO` and `$OPENREPOSHAPE_REF`.** The command checks
  both once, before `--version` answers and before any fetch, so a control
  character or a character a terminal draws as another in either is
  refused, exit 2, and never printed or sent, where `--version` printed
  both as typed. `--help` still answers first, and names the variables,
  never their values (#872, #866).
- **CI on a release branch.** `tests.yml` runs on a push to a
  `release/v<major>.<minor>` branch that holds this change as on a push to
  main, so a patch's commit there gets its own push run with no dispatch.
  Its concurrency group includes the ref, so a fast-forward of that branch
  to main's commit no longer cancels main's run on it. `release.yml`'s
  comments say how a patch is cut from `release/v<X.Y>` and how a fix is
  back-ported; its YAML is unchanged. `release/v1.0` does not hold the
  change and still needs a dispatch (#852, part of #850).
- **Tests.** Tests append what they tell git to the `GIT_CONFIG_COUNT`
  entries the environment holds, through `appended_to_command_scope`, so a
  pasted line keeps the session's maintenance settings and the Windows
  job's two entries, and a scan fails a test that sets a count of its own
  (#818, #758; #848, #835). The doctor tests' `paste()` gives a pasted
  `git submodule update` the `insteadOf` rewrite, so it reads a test's bare
  remote through git's transport (#848, #835). The quoting-sentence
  inventory sees a quoter handed on as a value, and the launcher guard
  reads `run_child` and `run([PYTHON, ...])`, with rows for
  `src/openreposhape/cli.py` and `setup-project.py` (#808, #759). The tests
  that need a name that is not UTF-8 ask one helper whether one can be
  made, and skip on its two answers only, so a full disk or a folder nobody
  can write in fails them, where they read as SKIPPED (#806, #757). None of
  these changes a shipped file.
- **The docs.** README.md and the handbook say that `family.py init`'s
  `--into` refuses its default inside a checkout of the standard
  (`family-landing-in-standard`), and describe `make siblings` as it stops
  before cloning; one sentence in five places, AGENTS.md and the holder's
  README and `AGENTS-shape.md` among them, says that a holder keeps
  `members/` in one spelling (#738, #695). That closes a known limit
  v1.1.0 named. The holder's README and `AGENTS-shape.md` say its parent
  folder is named EXACTLY after its repository, case included, and
  AGENTS.md and `AGENTS-shape.md` say the validator may name a hand repair
  of a `members:` row, whose commit is then the person's (#822, #763).
  README.md and the handbook also say that Git Bash is handed `sh`'s
  quoting (#821, #711), that a path the doctor cannot print as itself is
  written `$'...'`, which dash does not run (#792, #785), and that a
  `.gitmodules` git refuses fails CI whatever the credential (#790, #786).

## Known limits

v1.1.0's [known limits](v1.1.0.md#known-limits) that this release does not
close still hold; this list is not all of them. Of the two that work on
v1.1.0 named and left open, this release closes the README's and the
handbook's `--into` sentence (#738, #695). The other,
`bump-leg.py --dry-run` exiting 0 over a pin its own validators refuse, is
unchanged but for one case: a `legs:` entry that is not a mapping is now
refused by the dry run as by the real run (#862, #832).

New in v1.1.1, from the pull requests that landed it:

- A project or a holder keeps v1.1.0's copies until `update-shape.py apply`
  re-pins it, and until then its own gates and `make bootstrap` behave as
  v1.1.0's: for example, they read a `tracking_branch:` ending in U+00A0 as
  the branch without it (#823, #715).
- A tracked name that the doctor sets aside before it walks a leg, one
  holding a control character or a byte that is not UTF-8, still counts in
  `plan`'s and `execute`'s extension-majority fold. So `engine/` holding
  `a.py`, `b.py`, `x.md` and `t<TAB>b.py` folds to code, 3 of 4, and the
  doctor, which sees 2 of 3, reads `code/engine/x.md` as MISPLACED, with the
  plan exactly as `plan` wrote it. It is on #457's checklist (#829, #801).
- A `--source` directory this user cannot enter, or one under a directory
  they cannot enter, still ends `adopt-project.py` in a `PermissionError`
  traceback, exit 1; it is reported for #457's checklist (#831, #796).
- A `--pin-source` inside a non-bare clone's git directory, such as
  `glass/.git`, is refused `pin-source-not-a-clone`, naming the git
  directory, although its digest would have been the whole tree's. A git
  that refuses a clone it finds (`safe.directory`, "dubious ownership") is
  "git finds no clone there", followed by git's own reason (#842, #800).
- A plan read at `--tracking-branch`, because the source's default branch
  had no local copy, records that branch as `source.default_branch`, and
  goes stale once the default branch is made local: `check` then reads the
  source at it, finds `plan-stale` where its commit is not the plan's, and
  `plan` is run again. The printed `git branch <b> origin/<b>` can bring
  back a branch the remote has since deleted, where the clone was fetched
  without `--prune` (#830, #797).
- Whether `--local-remote-dir` can be written in is asked with `os.access`.
  Root, and any folder on Windows, are always told yes, and an ACL that
  says otherwise is met at the `mkdir` or `git init`, after nothing, or
  after the spec leg, was made. A private repository the token cannot see
  answers as not found, so `execute` keeps its notice for what can fail
  after the first create. A name that GitHub only redirects, after a rename
  or a transfer, is free, and `gh repo create` takes it over, which ends
  the redirect; neither `check` nor `execute` says so. `check` without
  `--local-remote-dir` needs `gh` for a clean read; offline it passes, with
  a NOTE (#861, #798).
- `update-shape.py apply` refuses, before any write (#286), a root that
  keeps a symlinked directory above a pinned copy, such as `.github -> ci`,
  so it never extends the line-ending block with the tracked spelling; the
  link is replaced first, as the remedy says (#844, #807).
- `update-shape.py apply --branch <new>`, run from a branch whose name is
  not UTF-8, is refused, exit 2, before anything is written, where v1.1.0
  committed and pushed the new branch, or said `nothing to do`; `apply`
  without `--branch` runs as before, and the way out is one `git branch -m`.
  `family.py`'s dry runs on such a branch print their plan and then refuse,
  exit 2 (`bump --dry-run` has fetched in the member by then), and no test
  holds that refusal; their real runs refuse before anything is fetched or
  written. A push line naming a branch that holds U+2028 or U+0085 names it
  exactly, inside single quotes, so a viewer that breaks lines there shows
  the line broken (#849, #765).
- The commands a remedy prints for a person to paste, such as
  `family.py`'s `switch -c`, `add` and `rm -f` lines, are quoted for a
  shell, and still hold a name holding a control character raw inside the
  quotes; the follow-ups are on #459 and #458 (#814, #766).
- A path the doctor cannot print as itself is written `$'...'` off Windows
  and in Git Bash, which bash, zsh and ksh run and dash does not; README.md,
  the handbook and AGENTS.md say so. Its PowerShell spelling is held as
  text, and was not run in PowerShell (#792, #785).
- A PowerShell started from inside Git Bash inherits `MSYSTEM`, so it is
  handed Git Bash's quoting; the handbook says so (#821, #711).
- On Windows, a `.gitmodules` section name that is not UTF-8 is still not
  found by the doctor (#774, #732).
- In a root that lost `scripts/repo_shape.py`, the doctor's `agent-files`
  row's WHY still says to run the root's own `validate-pins.py`, which
  exits 1 with `ModuleNotFoundError` (#776).
- A dangling Windows junction at `../<Project>` still reads as an empty
  slot to `make siblings` and to the doctor (#793).
- Where git's update fails, a holder's `make bootstrap` still prints the
  `SHAPE_LEGS_TOKEN` advice above a line that says "not for want of a
  credential", where no token can help (#839).
- A `.gitmodules` in the index or HEAD with one line git cannot parse is
  read by a holder's `make bootstrap` as no sections, where git reads the
  sections before that line, so a run with no credential fails where only
  the credential was missing. The value rules are written twice, in the
  holder's `bootstrap.py` and its `validate-family.py` (#856).
- A `path` key with no value in HEAD's `.gitmodules` is reported by
  `validate-family.py` twice, as `gitmodules-value-refused` and as
  `member-gitmodules-absent`; both lines write the same path back, so
  typing both is harmless (#819, #768).
- `validate-family.py`'s reading of where `git submodule init` stops is
  simpler than a holder bootstrap's: for a section name with a `..`
  component, a url beginning with `-` or an unmerged `.gitmodules`, its
  refusal keeps the plain update, which dies. Its `git rm --cached` line
  for a stray gitlink that a sparse checkout keeps off disk has no
  `--sparse`, so it exits 1, with git's own hint (#820, #762).
- `validate-family.py`'s wrong-case move back guards its `mv` without
  `family.py`'s "nothing there" test, so the `mv` exits 1 where nothing is
  at the variant (#828, #761). `family.py add`'s case-spelling remedies
  still miss some states, among them a section that gives a case variant
  of a row's path while the gitlink is at the row's path (#840), and an
  unmerged file at or under a row's path keeps #574's remedy (#828, #761).
- `setup-project.py`'s refusal of a project name explains only a leading
  `-`; a trailing space passes the prompt and ends at step (4), where a
  leading one is refused at once; and a name of 101 to 255 characters
  passes the prompt and ends at step (5) or at GitHub (#777). A refused
  name ends the run, with no second prompt (#756, #729).
- A lone `0x9B` byte in `$OPENREPOSHAPE_BIN_DIR` is placed: a terminal that
  reads UTF-8 draws it as a character it cannot read, and only one set to
  an 8-bit charset acts on it (#867, #858).
- A multibyte locale that is not UTF-8, left in a terminal that reads UTF-8,
  is handed the C1 bytes that the locale reads as letters, and that terminal
  acts on them. No GB18030, GBK or Shift_JIS locale was built: the tests
  stand in a `locale` that answers `locale charmap` as glibc does (#867,
  #858).
- Windows and macOS: CI runs on Linux only (#597), but for the launcher's
  and `install.sh`'s suites, which it also runs on Windows in Git Bash. A
  disk that folds case (#820, #828), Git Bash's and PowerShell's quoting
  (#821, #792) and a Windows disk refusing a name (#806) are emulated in the
  tests, not run there, and macOS's `[[:cntrl:]]` was not measured for C1
  controls (#804).
- The tests' scan for a `GIT_CONFIG_COUNT` set by hand does not read a key
  name imported from another module, a value built by `format()`,
  `repr()` or `os.fsdecode()`, a conditional value, `setenv` with
  keywords, an annotated subscript, a value held in a variable and set
  later, or an indexed `GIT_CONFIG_KEY_<n>` name; not a product bug (#848,
  #835).
- Tests in `test_cli_reference.py`, `test_doctor_validator_verdicts.py`,
  `test_bootstrap_leg_moves.py` and `test_adopt_template_values.py`, and
  the `make_file` helper, still skip on any `OSError`, so a full disk or a
  read-only `tmp_path` reads as SKIPPED; not a product bug (#834).

## How this release is cut (remove at tag time)

<!-- remove at tag time -->

v1.1.1 is cut from `release/v1.1`, on Brett Heap's word of
2026-10-18T01:05:28Z, which chose #850's option A. Main stays the trunk:
every change lands there first, through its own review, CI and gate. Lane
openRepoShape-3, the release owner, fast-forwards `release/v1.1` to main
after each landing, so the branch holds main's commits and no other. If a
pull request that is not v1.1.1 work lands on main, `release/v1.1` takes
v1.1.1 fixes from then on by back-port only (#473 issuecomment-6244650070):
a pull request to `release/v1.1` of `git cherry-pick -x <squash>`, as
`release.yml`'s header says.

This notes pull request lands last, as the release commit, under lane 3's
freeze, and lane 3 reviews it. The tag goes on that commit, at
`release/v1.1`'s tip. `.github/workflows/release.yml` publishes the wheel,
and its header's "RELEASING TO PyPI" and "RELEASE BRANCHES AND BACK-PORTS
(#850)" are the authority for these steps. The acts made once, which
[v1.1.0's notes](v1.1.0.md) record, are not made again; the build job
checks the two environments before every dispatch.

1. **The release commit passes `tests` on itself.** `release/v1.1` holds
   #850's `tests.yml`, so the fast-forward of `release/v1.1` to the release
   commit starts the branch's own push run on it, beside main's push run
   that landed it. The branch's newer run decides: tag once every
   `tests.yml` run on the commit has finished and the newest is green. A
   pull request's run, or a run on another commit whose tree is the same,
   does not count. Where no finished green run tested the commit, dispatch
   `tests.yml` on a branch at it before tagging, and wait for `tests` to
   pass:

   ```sh
   git push origin <release-commit>:refs/heads/<branch>
   gh workflow run tests.yml --ref <branch> -R opensoft/openRepoShape
   ```

2. **Tag that commit, annotated, and push the tag.** The build job refuses
   a commit that is on neither `main` nor `release/v1.1`:

   ```sh
   git tag -a v1.1.1 <release-commit> -m "openRepoShape v1.1.1"
   git push origin refs/tags/v1.1.1
   ```

3. **Dispatch the release workflow on the tag, with the version:**

   ```sh
   gh workflow run release.yml --ref v1.1.1 -f version=1.1.1 \
       -R opensoft/openRepoShape
   ```

4. **Brett Heap approves the `testpypi` deployment;** an approval is his
   act, never a session's. The install check then runs on ubuntu, macOS and
   Windows and on Python 3.9, and he approves the `pypi` deployment only
   once it has passed. A failed job is re-run with "Re-run failed jobs",
   never by re-running the whole run or dispatching the version again.
5. **Only then create the release, with `install.sh` attached,** from a
   checkout at `<release-commit>`, with these notes cut down to their
   published sections and every placeholder filled. v1.1.1 is the newest
   release of the newest line, so it is marked latest, and the one line
   then installs it:

   ```sh
   gh release create v1.1.1 install.sh --verify-tag --latest \
       --title "openRepoShape v1.1.1" --notes-file <notes> -R opensoft/openRepoShape
   ```

6. **Check the published asset, by redirect and by bytes,** as v1.1.0's
   step 6 does, with `v1.1.1`:

   ```sh
   curl -fsSI --proto '=https' --proto-redir '=https' \
       https://github.com/opensoft/openRepoShape/releases/latest/download/install.sh
   curl -fsSL --proto '=https' --proto-redir '=https' \
       https://github.com/opensoft/openRepoShape/releases/latest/download/install.sh \
       | cmp - <(git show v1.1.1:install.sh)
   ```

   The first must answer with a `location:` naming
   `…/releases/download/v1.1.1/install.sh`; the second, run in bash or zsh,
   must print nothing and exit 0.

A version is uploaded once. A bad upload is fixed by the next patch, never
by moving a tag.
