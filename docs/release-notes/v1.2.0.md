v1.2.0 is a minor release, the next after v1.1.1. It adds no command and no
flag. It adds refusals and findings, each under its own code, where a tool
read a path it could not read as absent, ended in a traceback, or said `ok`
and failed later, after a repository or a leg was made. It fixes how
`adopt-project.py check` rehearses the split, how the YAML reader takes a
key written twice and a block scalar, how `bump-leg.py` and `family.py bump`
fetch, how a holder's `make bootstrap` says where git's update stopped, and
what the scaffold, setup and both `openRepoShape` commands refuse before
they act. It changes pinned shape copies, so a project or a family holder
takes those fixes into its own gates by `update-shape.py` (below). It is
tagged on main.

## What 1.2.0 fixes

- **A path this user cannot read is named, never read as absent.** From
  Python 3.14, `Path.is_file()`, `is_dir()` and `exists()` answer False to
  any `OSError`, so a path this user could not search read as one that was
  not there; up to 3.13 they raise, and the run ended in a traceback. Every
  shipped tool now refuses such a path by name, on every Python, but at
  eleven sites left to #1110 and over a root's own `.git` (#1146, #1148;
  see the known limits), and a test holds each tool's guards to that rule
  (#934, #976, #975, #958, #956, #951, #955, #970, #1072, #1111, for #430).
- **`adopt-project.py check` finds what `execute` would meet.** It
  rehearses the split in the work directory, with the source's object
  format and none of this machine's hooks; it names a symlink target no
  system can make (a NUL after its first byte, or over 4095 bytes), a link
  into the clone's `.git` and a pin's file reached through a kept link; and
  it refuses a hand-edited plan value read as a number or a boolean, each
  before either leg exists (#1031, #965, #1070, #1091, #1016). `plan` asks
  its flags' own refusals before it clones, and `check` and `execute` name
  the same first problem (#963, #1015).
- **The YAML reader refuses a key written twice,** and reads a block
  scalar as YAML does or refuses it by its line (#974, #1021). The scaffold
  and `adopt-project.py` spell a `neutral_product_pins:` entry one way,
  quoted wherever a stock reader would misread it (#995, #1090).
- **Fetches that answer for a branch.** `bump-leg.py` and `family.py bump`
  no longer move the mount's own branches, and leave out every refspec that
  can bring a tag, or that puts a branch under another name, through one
  rule both import (#937, #946, #1027, #1068, #1087). A commit only a tag
  reaches is named so, whichever kind of tag reaches it (#988).
- **A holder's `make bootstrap` fails by name where git's update
  stopped:** at a gitlink with no url, at a commit a fetch did not bring,
  or where a signal ended git, where it said `family bootstrap ok`. A token
  reaches no trace, a member's make under `make -jN` no longer warns of the
  jobserver, and the FAILED line names the member's own exit code past a
  `-` make, or past `|| true` and a `-` command (#889, #954, #1045, #1076,
  #1075, #950, #1023, #891). `validate-family.py`'s remedies type as
  printed, in order (#889, #1025, #1069).
- **The scaffold and setup.** A push or a seed fetch no longer waits at
  git's username prompt, a login or key the host refuses names its fix, and
  the help says what can still make the re-run wait (#971, #1012, #1101);
  the plan names the tracking branch and, on disk, the visibility (#969); a
  flag passed empty is refused by name (#972, #1010); a Windows device name
  is refused (#1010, #1041); and setup's credential-helper check and its
  step (4) read what the run will meet (#1008, #1022, #949, #1011).
- **Both `openRepoShape` commands.** The one `pipx` places refuses what the
  bash one refuses wherever it prints a value or hands one to git (#947);
  under the `C` locale a letter past ASCII is no longer "a control
  character", the regression v1.1.1 named (#986); and the bash `--doctor`
  checks the ref before it clones (#967).
- **Lines a person pastes.** `make bootstrap`'s `merge --ff-only`,
  `--continue`, `--abort` and `submodule update` lines give a leg's path
  and an upstream as one shell word (#944, #973); the split message names
  each path as `plan` shows it (#1030); and every remedy that names
  `family.py bump` names `--family-root` (#1002).
- **A leg on a branch spelled like the tracking branch.** `make bootstrap`
  leaves a leg whose branch folds to the tracking branch on macOS or
  Windows (`Main`, or another Unicode form), where it moved the branch
  under HEAD and left the index at the old commit (#948, #984, #1006).
- **CI.** The full suite and the Python 3.9 jobs run on `ubuntu-24.04`
  (#1095), the release's install check runs the doctor over a scaffolded
  root (#945), and every release's notes are held to the one-line install
  (#887, #959).

## Install and upgrade

- **The newest release, by the one line:**

  ```sh
  curl -fsSL https://github.com/opensoft/openRepoShape/releases/latest/download/install.sh | bash
  ```

  It places the bash `openRepoShape`. The same line again upgrades.
  `… | bash -s -- v1.2.0` names this release. `openRepoShape --version`
  prints `openRepoShape (opensoft/openRepoShape @ v1.2.0)`.
- **From PyPI:** `pipx install openreposhape==1.2.0` for this release, and
  `pipx upgrade openreposhape` to upgrade one already installed.
  `openRepoShape --version` prints
  `openRepoShape 1.2.0 (opensoft/openRepoShape @ <release-commit>)`.
  [v1.1.0's notes](v1.1.0.md#install-and-upgrade) say where `pipx` comes
  from, and that the two installers do not replace each other's command.
- **A project's and a holder's shape copies.** A copied file reaches no
  project by itself. v1.2.0 changes five of the copies an assembly root
  pins: `scripts/validate-pins.py`, `scripts/validate-manifest.py`,
  `scripts/bootstrap.py`, `scripts/repo_shape.py` and
  `scripts/validate-repository-naming.py`. It changes four of the copies a
  family holder pins: `scripts/validate-family.py`, `scripts/bootstrap.py`,
  `scripts/siblings.py` and `scripts/repo_shape.py`. No `Makefile`,
  `.gitignore`, `.gitattributes`, `validate.yml` or `AGENTS-shape.md`
  changes, nor the naming policy. **[placeholder: if #1142 lands before
  the tag, both roots' `.github/workflows/validate.yml` joins these lists.]**
  From a checkout at the v1.2.0 release commit,
  `update-shape.py check --root <path> --at <release-commit>` reports
  each as `upstream-changed` in a root pinned at v1.1.1 that has not
  edited it, and
  `update-shape.py apply --root <path> --at <release-commit> --yes --branch shape/update-<sha>`
  re-copies and re-pins them, on the person's yes, as AGENTS.md's
  "Updating a project's shape" says. Until then the root's own gates and
  `make bootstrap` are v1.1.1's.
- **A holder that keeps its own `scripts/bootstrap.py`.** The new
  `siblings.py` imports `member_make_environment` (#1023) and `untraced`
  (#1075) from the holder's `bootstrap.py`. From a pin at v1.1.1 or
  earlier, `bootstrap.py` changed upstream, so a kept copy reads `both`: a
  plain `apply` refuses `update-conflict`, and `apply --accept-local
  scripts/bootstrap.py` refuses `update-accept-local-missing-name`, both

  not asked again, reaches only a holder pinned at a main commit between

  new `siblings.py`, and `make siblings`, `make park` and `make resume`

  `bootstrap.py` into the kept copy by hand, or take the upstream's bytes;
  commit, and run `apply` again.
- **A YAML layout the new reader refuses.** A project keeps its old
  `repo_shape.py` until `update-shape.py apply`, and the old copy reads the
  last of a key written twice without a word, so a `project.yaml` that
  holds a key twice passes its own `validate-manifest.py` until then. At
  `apply` the new copy refuses it, `yaml-unparsable` with the line of the
  second key, then `update-validators-red`, then ROLLED BACK. Delete the
  first of the two lines to keep the reading the project has now, and run
  `apply` again. A block scalar's indentation digit (`|2`, `>-2`, `|2-`)
  ends the same way; with the digit deleted the value reads as before,
  except where the header also holds `-` or `+`, or the body holds another

- **The rendered READMEs, and a holder's `cd` line.** A project's or

## What changed since v1.1.1

v1.1.1 was tagged on `5017830` on 2026-10-18. Everything below landed on
main after that commit, by area; `release/v1.1`, which holds v1.1.1, takes
none of it. The list runs to the commit v1.2.0 is tagged on. Each bullet
names its pull request, then the issue it closed or took a part of.

### adopt-project.py

- **`plan` asks its flags first.** `plan` asks the refusals that a flag's
  own value decides straight after `--out`, before it makes a work
  directory, reads the source with git or runs `gh repo clone`: `--project`,
  a passed `--tracking-branch`, the leg paths and their collisions, the
  `--pin` refusals, a passed `--id`, `--org`, `--elected-on`, `--elected-by`
  and `--reference`. Each keeps its code and its words; only when it is
  asked moved. An `org/repo` source is held to its own name before the
  clone too: `--project Other` against `testorg/Thing` is
  `adopt-not-the-source`, and an id derived from `--project` that is no id
  (`--project North_Wind`) is `adopt-bad-id`, with no `gh` call, where each
  was said after the clone. An unwritable `--work-dir` says why `plan`
  cannot clone into it ("and `plan` clones testorg/Thing into
  `source-readonly/Thing` there"), and a local source's `--work-dir` is no
  longer probed for a write (#963, #903).
- **An empty flag is a value.** `--org ''` is `unsafe-value`, refused with
  the other flags. It was counted as given in one place and as not given in
  another, so a refusal named `--org is '~x'`, which nobody typed, and
  `adopt-not-the-source` said "(`--org` not given)". `--elected-on ''` is
  `election-date-malformed` and `--reference ''` is
  `adopt-manifest-invalid`, in the validator's words; both exited 0 and
  recorded today's date or the default reference. A plan's own
  `reference: ""` is `plan-manifest-invalid` in `check`, and `execute`
  refuses it before any leg, where it wrote the default reference without
  a word (#1016, #902).
- **A plan value read as a number or a boolean.** `check` and `execute`
  refuse a hand-edited plan whose `id:`, `tracking_branch:` or
  `adopt_branch:` the plan's reader reads as a number or a boolean, such as
  `id: 007`, `tracking_branch: 007` or `adopt_branch: true`. The code is
  `plan-bad-id`, `plan-bad-tracking-branch` or `plan-bad-adopt-branch`, and
  the words say what was read ("`id:` was read out of the plan as the
  number 7, not as text"); `execute` refuses it before any leg exists.
  Before, `id: 007` was adopted and `project.yaml` said `id: "7"`,
  `tracking_branch: 007` was adopted onto a source branch `7`, and
  `adopt_branch: true` pushed the split to a branch `True`. The remedy is to
  write the value between double quotes, as typed, or to run `plan` again,
  which writes every value so that it reads back as typed (#1016, #902).
- **Id and name refusals say the rule.** A plan with no `id:` whose
  `legs.assembly`, lowercased, is no id is `plan-bad-id` saying so ("id
  (not set in the plan, so legs.assembly lowercased) is 'north_wind'"), and
  its remedy says to change `legs.assembly`, where it named an `id:` nobody
  set. A passed `--id`, or a plan's `id:`, that is no id is told what an id
  may hold: lowercase letters, digits and hyphens, starting with a letter or
  digit, in the scaffold's words. Where the source is adopted in place, the
  naming refusal says the rule for the new name, one CamelCase token with no
  hyphen, underscore, dot or space, before it says to rename the source
  first; `adopt-not-the-source` and `plan-not-the-source` say that the
  source's own name is no remedy where the naming policy refuses it. A
  refused name speaks before a passed `--id`'s. AGENTS.md's adoption step
  says that `--org` defaults to the organisation of an `org/repo` source or
  of a url `origin`, and that a path `origin`, or none, needs `--org`
  (#1016, #902).
- **One first problem in a hand-edited plan.** `check` and `execute` ask a
  plan's `org:` and `id:` before its leg paths and branch names, so both
  name the same first problem where a plan has more than one. A plan with
  `id: "North Wind"` and `legs.spec_path: "../spec"` was `plan-bad-id` in
  `check` and `plan-bad-leg-path` in `execute`; it is `plan-bad-id`, exit
  2, in both, and an unsafe `org:` beside the same path is `unsafe-value`
  in both. A `pins:` entry that the pin reader names is that one finding: a
  pin edited to `product: "a<TAB>"` was three findings,
  `plan-pin-malformed`, `plan-unwritable-value` and `plan-manifest-invalid`,
  and is `plan-pin-malformed` alone. A `pins:` that is no list is said as
  the reader says every other key ("`pins:` is the boolean true, not a list
  of pins"), and a finding about a pin's `digest_source:` says that
  `execute` writes the pin file from the commit and the digest `plan`
  records, "and how it was read, and nothing else" (#1015, #901).
- **A name no Windows disk can make.** `plan --project NUL`, and `Con`,
  `com1` and `Lpt9`, in any case and with or without an extension, is
  refused as `adopt-bad-project-name`, exit 2, with the other flag
  refusals, before a work directory, git, `gh` or a plan file exists.
  Before, it wrote a plan and exited 0. `--project` names the assembly root
  and the folder `execute` clones it into, and no Windows disk can make a
  file or a folder of a device name. `check` finds the same name in a
  plan's `legs.assembly` as one FINDING, exit 1, and asks `gh` nothing,
  where it said `plan ok` after two `gh repo view` calls; `execute` refuses
  it. It is the one question `scaffold-project.py` and `family.py init` ask
  (#1010), and the first of the names `execute` cannot make. Where
  `--project` is the source's own name, the remedy gives the way out in
  place, to rename the source on GitHub first. A name the naming policy
  refuses as well, such as `NUL.git`, keeps the refusal it had:
  `naming-unclassified` with an `--id`, and `adopt-bad-id` for the derived
  id without one (#1041, #1014).
- **A source this user cannot reach.** A `--source`, or a plan's recorded
  `source.local_path`, that this user cannot reach, one under a directory
  it cannot search, is `source-unreadable`, exit 2, with the `chmod u+rx`
  cure for the directory and every directory above it. It is never read as
  absent and never sent to `gh`: an `org/repo` spelling beside an
  unreadable `./org` is not cloned, and a recorded source is neither
  `plan-source-gone` nor cloned again. On Python 3.12 these were a
  `PermissionError` traceback; on 3.14, where `Path.exists()` answers False
  to any `OSError`, a `--source` was `source-unresolvable`, an `org/repo`
  spelling was cloned from GitHub, and a recorded source was
  `plan-source-gone` or cloned again. A leg under `--local-remote-dir`
  whose `stat` is refused waits for the leg question, which refuses the
  folder by name, `adopt-folder-cannot-be-made`, where 3.12 ended in a
  traceback. `plan-root-symlink` says of a place it cannot read "cannot be
  read (Permission denied), so whether anything is there cannot be told
  until this user can search every directory above it (`chmod u+rx`)",
  where it said "and nothing is there". `--source`'s help in docs/cli.md
  says so (#970, part of #430).
- **A source this user cannot enter.** A `--source` directory that is
  itself at mode 000 is `source-unreadable` too, where `plan` ended in a
  `PermissionError` traceback, exit 1. A recorded source in that state,
  which `check` called a clone "no longer whole (git finds no repository
  there)" and cloned again with one `gh` call, is the same refusal, before
  anything is cloned or written. A plan written in UTF-8 and read under
  `LC_ALL=C PYTHONUTF8=0` asks a recorded path that the locale cannot spell
  as the plan's UTF-8 bytes, so `check` says `plan ok` where it said
  `plan-source-gone`, as it does in UTF-8 mode; where those bytes name
  nothing either, the refusal says so, naming the locale ("this locale's
  file names, ascii, cannot spell it"). A one-byte locale such as Latin-1
  still asks only the spelling as written (#1072, #918).
- **`check` asks git as the split will meet it.** The throwaway
  repositories `check` makes, to rehearse the split, to probe
  `.gitattributes` and to ask how files are stored, are made in the work
  directory (`--work-dir`, or the one `check` makes in `TMPDIR`, never
  `TMPDIR` itself) with the source's object format and none of this
  machine's hooks, and each names its branch. A SHA-256 source, which ended
  `check` in `git-failed` at the rehearsal's `read-tree`, is `plan ok`, and
  so is a SHA-1 source under `GIT_DEFAULT_HASH=sha256`. A path of the
  source commit that git refuses as a path (`..`, `.Git/x`,
  `notes/.git/x`) is the new finding `plan-path-git-refuses`, which names
  the paths and which `execute` refuses before it makes either leg, where
  `check` ended in `git-failed`. A repository git cannot make in the work
  directory is one finding, `adopt-git-unasked`, with git's reason, and
  `execute` refuses it before any leg. A symlink probe whose `git init`
  fails takes git to check symlinks out as symlinks and prints one NOTE
  with git's words, where `check` said "a git or gh command failed" (#1031,
  #910).
- **A symlink target that git cannot make.** `check` names a symlink whose
  target holds a NUL after its first byte, or is longer than 4095 bytes, as
  `plan-bad-symlink-target`, before any leg exists. `execute` refuses it as
  it refuses any `check` finding, and `plan` still writes the plan and
  notes it. Before, `check` said `plan ok` and `execute` stopped after both
  legs existed, with a clone that exited 128, "File name too long", or with
  `adopt-lost`. The finding says what git makes of the blob ("a link to
  `ci`, not to the 5 bytes the blob holds"), or the bound; 4095 is Linux's,
  and macOS and XFS take less (see the known limits). A root-kept
  `.github -> ci<NUL>xx` is no longer `plan-root-symlink` saying it leads to
  `ci\x00xx`. A link at `project.yaml` is one finding, `plan-empty-symlink`
  or `plan-bad-symlink-target`, ending with where the link sits and what
  ends the manifest block, where `plan-root-blocks-manifest` named it again;
  a link at a copy under `shape/`, or at a pin's file, is one finding too,
  where `plan-root-blocks-shape-copy` or `plan-root-holds-pin` named it
  again with a remedy, to send it to a leg or `drop` it, that cannot help a
  link no clone makes. `check` reads the link targets in one
  `git cat-file --batch`, not one `git cat-file blob` for each link, walk
  and disk (#965, #908; #1070, part of #979).
- **A link into the clone's `.git`.** `check` names what the clone's
  `.git` holds as git keeps refs: it asks a throwaway repository in the work
  directory whether this git uses the reftable format and writes reflogs. A

### update-shape.py, bump-leg.py and a project's own scripts

- **A path nobody may read is named, not taken for absent: `bump-leg.py`.**
  From Python 3.14, `Path.is_file()`, `is_dir()`, `exists()` and
  `is_symlink()` answer False to a `stat` the system refused, where up to
  3.13 they raise. So a path this user could not search read as one that
  was not there. The worst case was in `bump-leg.py`: on 3.14, with a
  project's `scripts/` at mode 444 or 000, it printed `SKIPPED` for both of
  the project's validators, committed the bump and exited 0. Now an
  unreadable validator is refused before anything is written, a dry run
  included, as `bump-leg-validator-unreadable`, exit 2, naming each file
  with the cure (`chmod u+r`, or the advice for a cause that is not a
  permission, such as restoring the file from the project's history). A
  validator that is not there is still `SKIPPED`. A leg's checkout it
  cannot search is `bump-leg-submodule-unreadable`, naming `<path>/.git`,
  and a root, or a directory above it, that it cannot search is
  `bump-leg-manifest-unreadable`, naming `project.yaml`, exit 2. Those two

- **The same, for a project's own `bootstrap.py` and
  `validate-manifest.py`.** The assembly root's two pinned scripts name a

  absent. With `scripts/` at 000, `bootstrap.py` on 3.14 said `SKIPPED` for

  scripts/validate-repository-naming.py: cannot be read (Permission
  denied)`, exit 2, before any validator runs. A `project.yaml` behind a

  where on 3.14 no leg was placed and the run said `bootstrap ok`. A leg
  whose `.git` it cannot read is named and left as it is. A cherry-pick
  stopped in a leg whose `sequencer/` it cannot read leaves the leg
  detached, named, where `bootstrap.py` put the leg on `main` on every
  Python. A `governance/` it cannot enter heads step (c)
  `register, if one is there:`, says why, and claims nothing from it, where
  3.14 said `authority is not wallet-carried in this org`. In
  `validate-manifest.py`, a declared referent's pin file behind such a
  folder is `yaml-unreadable`, exit 2, where 3.14 gave the finding
  `naming-referent-missing`. Both scripts are pinned copies, so a project
  takes them with `update-shape.py` (#958, part of #430).
- **`bump-leg.py`'s fetch.** The fetch of a leg prunes the branches its
  remote deleted, so a dry run no longer says it would pin a commit no
  branch reaches any more, and it moves no branch of the leg's own. It runs
  `git fetch -q --prune --no-prune-tags --refmap= <remote> <refspecs>`.

  bring a tag under `origin/`, and one that gives another namespace the
  branches' names. A branch and a tag of one name no longer fail the fetch,

  asks of a member, now one function, `origin_fetch_refspecs` in
  `scripts/shape_materialize.py`, that both tools import: the rule was two
  copies, and `family.py`'s had been fixed alone (#1068, #1037).

  `bump-leg.py` leave out of the fetch every refspec of the repository's

  that puts a branch under a name not its own (`x` onto `release/x`, every
  branch into a folder), so a repository whose only refspec is

- **A leg with no `origin`.** A leg whose `origin` was renamed or removed
  is told so. The fetch's note says it has no remote named `origin`, and

- **`update-shape.py`'s kept-copy check and a handler that raises.** The
  check behind `update-accept-local-missing-name` read an
  `except ImportError:` handler as a fallback for what it binds, and never
  asked whether the handler then raises. A kept copy that binds
  `NEW = None` and then re-raises, beside a `repo_shape.py` without `NEW`,
  was not refused, and Python stops on the `ImportError`. It is refused
  now. A bare `raise` hands the `ImportError` to the next `try` out, so a
  nested `try` whose outer handler binds the name still starts and is still
  kept. Any other `raise`, such as `raise X`, answers nothing, since
  whether an outer handler catches `X` depends on its list: a copy that
  raises an error of its own is refused where Python stops on it, and one
  whose outer `except ImportError:` would catch it, which Python starts, is
  refused too. A handler whose `raise` sits under an `if`, or inside a
  `with`, is still read as binding (#935, #897).
- **A byte-order mark, in the three line rewriters.** Since v1.1.1 every
  reader takes a leading byte-order mark off. The three line rewriters did
  not, so `update-shape.py apply` refused a pin whose first line is
  `commit:` after a mark as `update-pin-unrecognised` ("0 `commit`
  line(s)"), and a manifest whose first line is `shape:` after one as
  `update-manifest-no-shape`, and `bump-leg.py` refused a leg's pin the
  same way as `bump-leg-pin-unrecognised`. Each finds its key after any
  number of marks on the first line and writes the marks back as they
  were. A mark on a later line is still refused as before. A marked
  `shape:` on line 1 beside a second `shape:` header is refused by name,
  `update-manifest-unrecognised`, as the reader refuses that file, where
  only the second block was seen and rewritten (#1050, #933).
- **`make bootstrap`'s pasteable lines.** The
  `git -C <leg> merge --ff-only <upstream>` line printed when a leg is
  moved back, and the `--continue` and `--abort` lines for an operation
  stopped in a leg, give the leg's path and the upstream as one shell word
  that a shell reads back as the same bytes. A name that prints as itself
  is quoted as it was. Any other, a byte that is not UTF-8, a control
  character, a U+2028, a bidirectional control or a name the stdout cannot
  write, is `"$(printf -- '<octal escapes>')"`, which dash, bash and zsh
  read. An upstream of `origin/a`, the byte 0xff and `b` was printed as
  `'origin/a\udcffb'`, which `sh` reads as the characters it holds, so the
  line named no ref (#944, #932). A word that begins with `=` is quoted, as
  zsh expands a bare `=word` to the path of a command. The choice between
  the quoted word and the `printf` word follows the bytes git is handed,
  which are UTF-8 on Windows, and not the stdout's codec alone: under a
  latin-1 stdout, `origin/café` was quoted and printed as the byte 0xe9,
  where the ref holds 0xc3 0xa9. And the `NOT INITIALIZED` command is
  `git submodule update --init -- <word>`, the leg's path one word after a
  `--`, with `./` in front of a path that begins with `:` so git does not
  read it as pathspec magic. Before, `my spec` was two pathspecs, `sp'ec` a
  syntax error in every shell, `-spec` an option and `=spec` failed in zsh.
  A name that ends in a line feed or holds a NUL has no such word and keeps
  the text it had (#973, #961). `bootstrap.py` is a pinned copy.
- **`make bootstrap` and a branch that differs from the tracking branch
  only in case.** Where a leg's HEAD is on `Main` and the tracking branch
  is `main`, `bootstrap.py` leaves the leg where it is. No ref moves and
  none is made. It says where the leg is, why it is left, and the way out.
  On a disk that folds case, macOS or Windows, `Main` and `main` are one

  detached at the pin included. Only HEAD's own ref was asked before, and

  that differs in Unicode form is a twin too: names are compared in NFC
  first, so the NFD spelling of `café` is a twin of the NFC one, as APFS
  reads the two as one file. Where HEAD is on the twin and `main` is there,

### scaffold, setup, family and the shared readers

- **A key written twice is refused.** The YAML reader in
  `scripts/repo_shape.py`, which the tools and the validators in a project
  and a holder read their YAML with, refuses the second of a key written
  twice in one mapping, block or flow, by that line
  (`line 2: key 'a' is written twice`), where it kept the last without a
  word. A flow collection is named by the line it is on. `a` and `"a"` are
  one key, and so are `1` and `"1"`, because the reader reads every key as
  text. The same key in two mappings or two sequence items, or a repeated
  value, is not a key written twice and still reads. A block-scalar line
  indented less than the block's first line is refused by its line, where
  its first characters were cut; one that opens `#` ends the block as a
  comment, as YAML reads it. `update-shape.py`'s refusal of a manifest
  holding two `shape:` blocks now says the reader refuses a key written
  twice, and no longer says it keeps the last (#974, #917).
- **A block scalar is read as YAML reads it, or refused by its line.** A
  block scalar's indentation digit (`|2`, `>-2`, `|2-`, `|0`, `|10`) is
  refused by its header's line (`line 1: a block scalar's indentation
  indicator is not supported: '|2'`), where the digit was accepted and
  ignored, so `k: |2` over `    a` and `  b` read `'a\n'` and lost `b`. `+`
  keeps the empty lines at the end of the block, where it read as no
  indicator. A line of spaces deeper than the block is text. A blank line
  above the first line of text that holds more spaces than that line is
  refused by its line, and so is a tab left of the block's column in a line
  that holds nothing else. A folded block keeps the line breaks around a
  line that opens with a space or a tab, and a block with no line of text
  reads `''`, where it read `'\n'`. A seeded differential against PyYAML
  6.0.3, over two runs of about 15,000 and 23,000 generated documents,

  6,000 in each. No tracked YAML file and no tool writes any of these
